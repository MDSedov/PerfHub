# PerfHub

PerfHub — внутренняя веб-утилита для сопровождения нагрузочного тестирования.
Она помогает находить тесты, смотреть метрики, сохранять конфигурацию стенда,
проверять требования и готовить отчеты в Confluence.

## Возможности

- поиск нагрузочных тестов по данным VictoriaMetrics;
- просмотр графиков Grafana за точный период теста;
- сохранение снапшотов конфигурации DropApp;
- проверка тестов по нефункциональным требованиям;
- генерация отчетов и страниц релиза в Confluence;
- хранение настроек подключений, шаблонов отчетов и дашбордов.

## Основной процесс

1. Заполнить подключения в разделе "Настройки".
2. Настроить дашборды, панели и требования.
3. Найти нужные тесты в разделе "Тесты и отчеты".
4. Проверить требования, добавить комментарии и конфигурацию.
5. Сформировать отчеты в Confluence по шаблонам.

## Локальный запуск

Нужны JDK 17 или новее и Maven.

```bash
mvn spring-boot:run
```

Приложение будет доступно по адресу:

```text
http://localhost:6500/main
```

Порт задан в `src/main/resources/application.properties`.

## Диагностика каталога Grafana

Если у Grafana показан `Каталог: PARTIAL`, `STALE` или `UNAVAILABLE`, либо у графика написано «Применимость не определена»:

1. Запустите обновлённый PerfHub обычным способом, без Debug.
2. Откройте **Настройки → Подключения** и выполните **Проверить** для Grafana.
3. В уведомлении или подсказке статуса каталога найдите путь к отчёту и ID проверки.
4. Откройте папку `logs` в рабочем каталоге запущенного PerfHub и пришлите указанный файл `grafana-catalog-diagnostics-user-<id>.txt`.

При запуске `mvn spring-boot:run` из корня проекта папка `logs` появится в корне проекта. В IntelliJ расположение определяется полем **Working directory** конфигурации запуска. Отладчик и ввод выражений не требуются.

В отчёте есть этап сбоя, категория причины и HTTP-код, если ответ получен. Адреса, токены, заголовки, тексты ответов и значения переменных в него не включаются. Общий журнал приложения присылать не нужно.

При получении deployment PerfHub сначала использует прежний datasource proxy. Только если этот запрос вернул HTTP 404, выполняется один дополнительный запрос через resources API того же datasource с теми же параметрами. Другие ошибки не запускают этот маршрут. Если дополнительный запрос тоже завершился ошибкой, в том же отчёте будет этап `DEPLOYMENT_VALUES_RESOURCES` и его фактический HTTP-код, если ответ получен. Это проверка совместимости маршрута; неверный datasource, ограничения прав или недоступность источника могут требовать другого исправления.

После обновления версии повторите **Проверить** для Grafana и заново откройте редактор шаблона. При успехе появятся полученные варианты deployment; успешный пустой ответ даст EMPTY. Если ошибка сохранилась, пришлите новый диагностический файл с ID этой проверки.

Каждая проверка заменяет предыдущий отчёт этого пользователя, в том числе после успешного обновления. Файл содержит ID последней записанной проверки; при параллельных проверках сопоставляйте его с уведомлением. Размер ограничен 128 КиБ и 100 записями ошибок, пропуски посчитаны отдельно.

Если файл сохранить не удалось, уведомление явно сообщит об этом; прежний файл не является отчётом новой проверки. Результат подключения и обновления каталога при этом сохраняется, а безопасное резюме с ID проверки остаётся в консоли. Диагностика помогает установить причину сбоя; сама по себе она не исправляет корпоративный API или его права.

## Настройки и база

Внешние настройки базы лежат в:

```text
config/application.properties
```

По умолчанию используется H2:

```text
./config/perfhub-db
```

Настройки интеграций можно менять через интерфейс PerfHub. Экспорт настроек может
содержать токены и ключи доступа, поэтому его нужно хранить осторожно.

## Сборка

Полная сборка с тестами:

```bash
mvn clean package
```

Сборка артефакта без тестов:

```bash
mvn -DskipTests clean package
```

Готовый JAR:

```text
target/perfhub-0.0.1-SNAPSHOT.jar
```

## Запуск JAR

```bash
java -jar target/perfhub-0.0.1-SNAPSHOT.jar
```

Пример запуска с явным портом:

```bash
java -jar target/perfhub-0.0.1-SNAPSHOT.jar --server.port=6500
```

## Проверка

```bash
mvn test
```
