# PerfHub

PerfHub — внутренняя веб-утилита для сопровождения нагрузочного тестирования.
Она помогает находить тесты, смотреть метрики, сохранять конфигурацию стенда,
проверять требования и готовить отчеты в Confluence.

## Возможности

- поиск нагрузочных тестов по данным VictoriaMetrics;
- просмотр графиков Grafana за точный период теста;
- сохранение снапшотов конфигурации DropApp;
- проверка тестов по нефункциональным требованиям;
- генерация отчетов и страниц релиза в Confluence;
- хранение настроек подключений, шаблонов отчетов и дашбордов.

## Основной процесс

1. Заполнить подключения в разделе "Настройки".
2. Настроить дашборды, панели и требования.
3. Найти нужные тесты в разделе "Тесты и отчеты".
4. Проверить требования, добавить комментарии и конфигурацию.
5. Сформировать отчеты в Confluence по шаблонам.

## Локальный запуск

Нужны JDK 17 или новее и Maven.

```bash
mvn spring-boot:run
```

Приложение будет доступно по адресу:

```text
http://localhost:6500/main
```

Порт задан в `src/main/resources/application.properties`.

## Проверка Grafana и каталога deployment

В **Настройки → Подключения** выполните **Проверить** для Grafana. После успешной проверки PerfHub обновляет каталог графиков и deployment; успешные состояния READY/EMPTY не создают отдельного уведомления или подписи каталога. В редакторе шаблона доступны полученные варианты deployment; при пустом ответе новые варианты отсутствуют.

Если каталог обновить не удалось, отдельно отображается PARTIAL, STALE либо UNAVAILABLE. В журнале остаются безопасные предупреждения с этапом, категорией и HTTP-кодом при наличии. Рутинное диагностическое INFO-резюме и автоматическая запись файлов grafana-catalog-diagnostics-user-*.txt отключены. Ранее созданные отчёты не обновляются и не удаляются.

При получении deployment PerfHub сначала использует datasource proxy. Только после HTTP 404 выполняется один дополнительный запрос через resources API того же datasource с теми же параметрами. При его отказе предупреждение содержит этап DEPLOYMENT_VALUES_RESOURCES. HTTP-код сам по себе не устанавливает причину: проверьте UID источника, доступ и сохранённые переменные dashboard. Имя источника и его UID могут различаться; после выбора источника сохраните в Grafana актуальные значения переменных.

После исправления подключения или переменных повторите проверку Grafana и заново откройте редактор шаблона.

## Настройки и база

Внешние настройки базы лежат в:

```text
config/application.properties
```

По умолчанию используется H2:

```text
./config/perfhub-db
```

Настройки интеграций можно менять через интерфейс PerfHub. Экспорт настроек может
содержать токены и ключи доступа, поэтому его нужно хранить осторожно.

## Сборка

Полная сборка с тестами:

```bash
mvn clean package
```

Сборка артефакта без тестов:

```bash
mvn -DskipTests clean package
```

Готовый JAR:

```text
target/perfhub-0.0.1-SNAPSHOT.jar
```

## Запуск JAR

```bash
java -jar target/perfhub-0.0.1-SNAPSHOT.jar
```

Пример запуска с явным портом:

```bash
java -jar target/perfhub-0.0.1-SNAPSHOT.jar --server.port=6500
```
