# grafana-visualization Specification

## Purpose
Предоставить каталог графиков и их изображения для теста либо выбранного периода с учётом шаблона отчёта и настроенных переменных.

Статус: baseline официально согласован владельцем 12.10.2026. Зафиксирован существующий AS-IS; уровни доказательств сохранены. Спорные вопросы остаются в реестре, без изменения функций, статусов, временных интервалов и источников порогов НФТ.

## Requirements

### Requirement: PH-GRAF-001 Каталог графиков

Система SHALL предоставлять сохранённый каталог dashboard и панелей и позволять обновлять его из настроенной Grafana.

#### Scenario: PH-GRAF-001-S01 Сохранённый каталог

- **GIVEN** каталог ранее сохранён, Grafana сейчас недоступна
- **WHEN** пользователь открывает список графиков в настройках
- **THEN** возвращается локально сохранённый каталог без обязательного запроса обнаружения.

#### Scenario: PH-GRAF-001-S02 Обновление каталога

- **GIVEN** Grafana возвращает dashboard с панелями, в том числе внутри rows
- **WHEN** пользователь запрашивает обновление
- **THEN** каталог содержит найденные панели и их доступные query/threshold; существующий выбор панелей отражается в ответе.

Доказательства и ограничения: [PH-GRAF-001](../../../docs/requirements/traceability.md#ph-graf-001).

### Requirement: PH-GRAF-002 Выбор графиков и переменных

Система SHALL сохранять настройки выбора панелей и значений переменных dashboard и использовать разрешённые значения переменных при получении изображений.

#### Scenario: PH-GRAF-002-S01 Сохранённая переменная

- **GIVEN** dashboard содержит переменную с выбранным непустым значением
- **WHEN** получается изображение его панели
- **THEN** в запросе рендера передано выбранное значение переменной.

#### Scenario: PH-GRAF-002-S02 Значение не определено

- **GIVEN** значение переменной dashboard не удалось определить
- **WHEN** получается изображение
- **THEN** не передаётся переменная с неразрешённым значением.

Доказательства и ограничения: [PH-GRAF-002](../../../docs/requirements/traceability.md#ph-graf-002).

### Requirement: PH-GRAF-003 Графики выбранного теста

Система SHALL возвращать изображения графиков из шаблона типа выбранного теста за период этого теста с идентификаторами и названиями панелей.

#### Scenario: PH-GRAF-003-S01 Графики получены

- **GIVEN** тест существует, его типу соответствует шаблон с графиками, Grafana возвращает PNG
- **WHEN** запрошены графики теста
- **THEN** возвращаются период, dashboard и панели с изображениями в base64 и названиями.

#### Scenario: PH-GRAF-003-S02 Нельзя определить графики

- **GIVEN** тест отсутствует, период недопустим либо шаблон отсутствует или не содержит графиков
- **WHEN** запрошены графики
- **THEN** возвращается ошибка с причиной; успешный набор графиков не имитируется.

#### Scenario: PH-GRAF-003-S03 Ответ не изображение

- **GIVEN** Grafana вернула успешный HTTP-ответ с содержимым без PNG-сигнатуры
- **WHEN** обрабатывается результат рендера
- **THEN** ответ не выдаётся как корректное PNG-изображение.

Доказательства и ограничения: [PH-GRAF-003](../../../docs/requirements/traceability.md#ph-graf-003).

### Requirement: PH-GRAF-004 Повторное использование изображений

Система SHALL переиспользовать подходящие сохранённые изображения теста, позволять принудительное обновление и предоставлять режим получения только уже сохранённых изображений.

#### Scenario: PH-GRAF-004-S01 Изображение сохранено

- **GIVEN** кеш соответствует тесту, шаблону, панели, периоду, переменным и параметрам изображения
- **WHEN** запрошены графики без forceRefresh
- **THEN** сохранённое изображение возвращается без повторного рендера этой панели.

#### Scenario: PH-GRAF-004-S02 Принудительное обновление

- **GIVEN** кеш существует, cacheOnly не включён
- **WHEN** запрошены графики с forceRefresh
- **THEN** изображение получается заново и сохраняется для последующего использования.

#### Scenario: PH-GRAF-004-S03 Только кеш

- **GIVEN** некоторые изображения не сохранены, forceRefresh не включён
- **WHEN** запрошен режим cacheOnly
- **THEN** возвращаются только найденные в кеше изображения; отсутствующие панели не рендерятся.

Доказательства и ограничения: [PH-GRAF-004](../../../docs/requirements/traceability.md#ph-graf-004).

### Requirement: PH-GRAF-005 Графики произвольного периода

Система SHALL предоставлять графики выбранного шаблона либо одну входящую в него панель за явно заданный допустимый период.

#### Scenario: PH-GRAF-005-S01 Период задан явно

- **GIVEN** существует шаблон с графиками
- **WHEN** переданы templateId и from/to, в том числе Unix-время в секундах либо миллисекундах
- **THEN** изображения соответствуют выбранному шаблону и периоду.

#### Scenario: PH-GRAF-005-S02 Панель не принадлежит шаблону

- **GIVEN** существует шаблон
- **WHEN** для одиночного рендера передан dashboardUid/panelId вне его графиков
- **THEN** операция отклоняется с сообщением об ошибке.

Доказательства и ограничения: [PH-GRAF-005](../../../docs/requirements/traceability.md#ph-graf-005).

### Requirement: PH-GRAF-006 Каталог базовых панелей DropApp для рендера

Система SHALL предоставлять базовые панели подтверждённого dashboard DropApp и сведения об их применимости к deployment из поддержанных Classic и `elements`/`variables`/`RowsLayout` представлений, сохраняя обычные панели. Неизвестный формат SHALL явно обозначаться без замены последнего корректного каталога пустым результатом.

#### Scenario: PH-GRAF-006-S01 Повторяемая строка нового формата

- **GIVEN** dashboard содержит элементы панелей и строку с repeat по `deployment`
- **WHEN** обновляется каталог рендера
- **THEN** доступны базовые панели строки с исходными идентификаторами и связью с deployment; динамические копии и сама строка не становятся дополнительными графиками.

#### Scenario: PH-GRAF-006-S02 Обычные панели и Classic rows

- **GIVEN** dashboard содержит обычные панели либо панели во вложенных Classic rows
- **WHEN** получен каталог
- **THEN** эти панели сохраняют исходные идентификаторы и доступность; отсутствие repeat не считается ошибкой.

#### Scenario: PH-GRAF-006-S03 Неизвестная структура

- **GIVEN** ранее получен корректный каталог, новый ответ не соответствует поддержанному формату
- **WHEN** выполнено обновление
- **THEN** показана ошибка обновления, предыдущий каталог сохранён; выбранные графики и значения не удаляются.

#### Scenario: PH-GRAF-006-S04 Панель не фильтруется по deployment

- **GIVEN** общая панель dashboard не имеет подтверждённой зависимости от deployment, в том числе через pod/container
- **WHEN** пользователь выбирает её в шаблоне
- **THEN** она не выдаётся за график выбранного deployment только на основании названия dashboard; сохраняется обычный режим панели.

### Requirement: PH-GRAF-007 Одно изображение deployment со всеми его pod

Система SHALL получать одно PNG на строку подходящего графика DropApp с конкретным deployment и всеми его pod и container, за период теста либо явно заданный период. Серии usage/request/limit и оформление SHALL определяться панелью Grafana, размеры — существующими общими настройками ширины/высоты. Выбор строки SHALL не менять общие переменные других строк и оценку НФТ.

#### Scenario: PH-GRAF-007-S01 CPU выбранного deployment

- **GIVEN** строка CPU настроена для `profile`, dashboard предоставляет серии usage/request/limit
- **WHEN** пользователь получает график
- **THEN** возвращается один PNG CPU со всеми pod `profile` и доступными request/limit; чужие deployment не добавляются из сохранённого общего выбора переменных.

#### Scenario: PH-GRAF-007-S02 Разные deployment одной панели

- **GIVEN** в шаблоне две строки одной CPU-панели для `profile` и другого deployment
- **WHEN** запрошены графики теста или периода
- **THEN** каждая строка получает собственное изображение со своим deployment; строки не объединяются и не переопределяют друг друга.

#### Scenario: PH-GRAF-007-S03 Явное разрешение всех pod и container

- **GIVEN** общие настройки dashboard содержат отдельный pod или container
- **WHEN** рендерится строка DropApp для конкретного deployment
- **THEN** используется режим всех его pod/container с учётом зависимостей переменных; общий отдельный pod/container не сужает результат и не изменяется в настройках.

#### Scenario: PH-GRAF-007-S04 Request и limit не становятся порогами НФТ

- **GIVEN** панель показывает request/limit как серии и содержит настройки отображения
- **WHEN** обновляется каталог рендера или получается изображение
- **THEN** существующие query/threshold, результаты, статусы и временные окна оценки НФТ не изменяются этой операцией.

#### Scenario: PH-GRAF-007-S05 Настроенный размер 1000 на 1000

- **GIVEN** существующие общие настройки ширины и высоты равны 1000 и 1000
- **WHEN** получается график DropApp для теста либо выбранного периода
- **THEN** рендер запрошен с размером 1000×1000 и возвращено соответствующее изображение; панель не получает отдельный жёсткий размер. При другом допустимом значении настроек применяется оно.

### Requirement: PH-GRAF-008 Различение строк и кеша изображений

Система SHALL различать строки шаблона одной базовой панели с разными deployment в запросах одиночного рендера, результатах и кеше. Переиспользование PNG SHALL учитывать источник Grafana, контекст dashboard, deployment, разрешённые переменные, период и параметры изображения. Прежние режимы forceRefresh/cacheOnly SHALL сохраняться.

#### Scenario: PH-GRAF-008-S01 Кеш другого deployment

- **GIVEN** сохранено изображение CPU/profile, запрошена строка CPU другого deployment
- **WHEN** ищется подходящий кеш
- **THEN** изображение profile не используется для другого deployment.

#### Scenario: PH-GRAF-008-S02 Одиночный запрос конкретной строки

- **GIVEN** шаблон содержит несколько строк одной панели
- **WHEN** передан идентификатор конкретной строки этого шаблона
- **THEN** рендерятся её deployment и название; идентификатор чужого шаблона либо несовпадение dashboard/panelId отклоняются.

#### Scenario: PH-GRAF-008-S03 Неоднозначный старый запрос

- **GIVEN** одна панель встречается в нескольких строках DropApp с разными deployment
- **WHEN** одиночный запрос содержит только dashboardUid/panelId без идентификатора строки
- **THEN** возвращается ошибка необходимости выбрать строку; первый deployment не выбирается молча. Прежний однозначный запрос остаётся допустимым.

#### Scenario: PH-GRAF-008-S04 Обновление и режим только кеша

- **GIVEN** для выбранного теста имеются кеши лишь части строк
- **WHEN** запрошен cacheOnly без forceRefresh
- **THEN** возвращаются только подходящие сохранённые изображения без запросов к Grafana; при последующем forceRefresh без cacheOnly выбранные изображения рендерятся заново.

#### Scenario: PH-GRAF-008-S05 Смена источника

- **GIVEN** изменились подключение Grafana, datasource, namespace либо определение панели DropApp
- **WHEN** запрошено изображение в новом контексте
- **THEN** прежнее изображение другого контекста не считается подходящим кешем.

#### Scenario: PH-GRAF-008-S06 Изменение высоты изображения

- **GIVEN** для того же теста, панели и deployment сохранено PNG 1000×500
- **WHEN** общая высота изменена на 1000 и запрошен график
- **THEN** PNG 1000×500 не считается подходящим для 1000×1000; обычный запрос получает изображение нужного размера, cacheOnly не рендерит отсутствующий вариант.

### Requirement: PH-GRAF-009 Ошибки и совместимость рендера

Система SHALL сохранять поведение обычных панелей и явно сообщать ошибки рендера DropApp без подстановки другого deployment или успешного изображения. Корректное PNG Grafana с отсутствующими данными SHALL сохранять своё изображение; пустой каталог выбора и транспортная ошибка SHALL не считаться доказательством отсутствия метрик за период.

#### Scenario: PH-GRAF-009-S01 Частичная ошибка получения

- **GIVEN** одна строка вернула ошибку транспорта, непустой ответ не-PNG либо пустое тело
- **WHEN** обрабатывается результат
- **THEN** строка не кешируется как успешное изображение; одиночный запрос сообщает ошибку, последовательный интерфейс периода показывает ошибку этой строки и продолжает остальные, пакетный запрос не объявляет полный успех.

#### Scenario: PH-GRAF-009-S02 Корректное изображение без данных

- **GIVEN** Grafana вернула корректный PNG с отображением «No data» для сохранённого deployment
- **WHEN** пользователь получает график за выбранный период
- **THEN** возвращается этот PNG с контекстом строки; PerfHub не подменяет его другой панелью, deployment или выдуманными request/limit.

#### Scenario: PH-GRAF-009-S03 Обычный график

- **GIVEN** строка содержит обычную панель без настройки deployment
- **WHEN** выполняются каталогизация, рендер теста/периода или чтение кеша
- **THEN** сохраняются прежние переменные, период, изображение, порядок, ошибки и режимы кеша; новый выбор deployment не требуется.
