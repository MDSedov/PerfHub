# requirement-evaluation Specification

## Purpose
Предоставить воспроизводимую оценку измерений нагрузочного теста относительно порогов его графиков и показать результаты пользователю.

Статус: baseline официально согласован владельцем 12.10.2026. Зафиксирован существующий AS-IS; уровни доказательств сохранены. Спорные вопросы остаются в реестре, без изменения функций, статусов, временных интервалов и источников порогов НФТ.

## Requirements

### Requirement: PH-NFR-001 Состав требований теста

Система SHALL определять проверяемые панели по шаблону типа выбранного теста и отклонять проверку, если соответствующий шаблон или его графики отсутствуют.

#### Scenario: PH-NFR-001-S01 Шаблон существует

- **GIVEN** тип теста имеет шаблон с панелями
- **WHEN** запущена проверка
- **THEN** результаты относятся к панелям этого шаблона, а не к посторонним сохранённым панелям.

#### Scenario: PH-NFR-001-S02 Нет шаблона или графиков

- **GIVEN** для типа теста не настроен шаблон либо он пуст
- **WHEN** запущена проверка
- **THEN** возвращается ошибка настройки без заявления о соответствии теста требованиям.

Доказательства и ограничения: [PH-NFR-001](../../../docs/requirements/traceability.md#ph-nfr-001).

### Requirement: PH-NFR-002 Сравнение числовых измерений с порогом

Для панели с заданными запросом и числовым порогом система SHALL сравнивать максимальное полученное числовое значение с порогом: значение не выше порога даёт PASS, превышение — FAIL.

#### Scenario: PH-NFR-002-S01 Значение в пределах порога

- **GIVEN** тест длиннее 6 минут, у панели есть query/threshold и VM возвращает измерения после исключения первых и последних 3 минут
- **WHEN** максимальное значение равно порогу либо ниже
- **THEN** панель получает PASS с измеренным значением.

#### Scenario: PH-NFR-002-S02 Порог превышен

- **GIVEN** для того же допустимого периода получены числовые данные
- **WHEN** максимальное значение превышает порог
- **THEN** панель получает FAIL с измеренным значением.

#### Scenario: PH-NFR-002-S03 Слишком короткий тест

- **GIVEN** есть хотя бы одна панель с query/threshold и длительность теста не больше 6 минут
- **WHEN** запущена числовая проверка
- **THEN** возвращается ошибка недостаточной длительности.

Доказательства и ограничения: [PH-NFR-002](../../../docs/requirements/traceability.md#ph-nfr-002).

### Requirement: PH-NFR-003 Актуальность повторно используемой оценки

Система SHALL переиспользовать сохранённую оценку только при её соответствии текущим проверяемым панелям, запросам и порогам; иначе SHALL выполнять новую оценку.

#### Scenario: PH-NFR-003-S01 Оценка актуальна

- **GIVEN** сохранены оценки всех текущих панелей с совпадающими query/threshold
- **WHEN** запрошен status
- **THEN** возвращаются сохранённые оценки без повторного запроса измерений.

#### Scenario: PH-NFR-003-S02 Порог изменился

- **GIVEN** у сохранённой оценки порог отсутствовал, а в текущей панели задан
- **WHEN** запрошен status
- **THEN** оценка пересчитывается по текущему порогу.

Доказательства и ограничения: [PH-NFR-003](../../../docs/requirements/traceability.md#ph-nfr-003).

### Requirement: PH-NFR-004 Представление результата проверки

Система SHALL возвращать результаты проверяемых панелей и общий результат для полностью оценённого набора числовых требований: все PASS дают соответствие, наличие FAIL — несоответствие.

#### Scenario: PH-NFR-004-S01 Все числовые проверки успешны

- **GIVEN** непустой текущий набор содержит только оценки PASS с измерениями
- **WHEN** получен результат проверки
- **THEN** compliant равен true; доступны результаты отдельных панелей.

#### Scenario: PH-NFR-004-S02 Есть нарушение

- **GIVEN** текущий полностью оценённый набор содержит FAIL
- **WHEN** получен результат проверки
- **THEN** compliant равен false; посторонняя старая оценка панели вне текущего шаблона не меняет состав проверок.

Доказательства и ограничения: [PH-NFR-004](../../../docs/requirements/traceability.md#ph-nfr-004).
