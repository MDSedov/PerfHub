# connection-settings Specification

## Purpose
Позволить настроить внешние подключения PerfHub, проверить их доступность и перенести поддержанные настройки с явным результатом операции.

Статус: baseline официально согласован владельцем 12.10.2026. Зафиксирован существующий AS-IS; уровни доказательств сохранены. Спорные вопросы остаются в реестре, без изменения функций, статусов, временных интервалов и источников порогов НФТ.

## Requirements

### Requirement: PH-CFG-001 Персональные настройки подключений

Система SHALL читать и сохранять параметры шести поддержанных подключений в контексте текущего пользователя; изменение персонального значения одного пользователя SHALL не изменять уже сохранённое персональное значение другого.

#### Scenario: PH-CFG-001-S01 Разные пользователи

- **GIVEN** у двух пользователей сохранены разные значения одного параметра подключения
- **WHEN** каждый запрашивает свои настройки
- **THEN** каждый получает своё значение.

#### Scenario: PH-CFG-001-S02 Изменение параметра

- **GIVEN** пользователь вошёл и передал service/key/value подключения
- **WHEN** параметр сохранён
- **THEN** повторное чтение этим пользователем возвращает новое значение; существующая персональная запись другого пользователя не изменяется.

Доказательства и ограничения: [PH-CFG-001](../../../docs/requirements/traceability.md#ph-cfg-001).

### Requirement: PH-CFG-002 Проверка подключения

Система SHALL позволять запросить проверку поддержанного подключения и возвращать идентификатор сервиса, признак успеха и сообщение о результате.

#### Scenario: PH-CFG-002-S01 Подключение доступно

- **GIVEN** для выбранного сервиса заданы настройки и проверочный запрос успешен
- **WHEN** пользователь выполняет проверку
- **THEN** возвращаются service, success=true и сообщение.

#### Scenario: PH-CFG-002-S02 Сервис недоступен или не поддержан

- **GIVEN** проверочный запрос завершился ошибкой либо имя сервиса не поддерживается
- **WHEN** выполнена проверка
- **THEN** возвращаются success=false и сообщение; успешное подключение не заявляется.

Доказательства и ограничения: [PH-CFG-002](../../../docs/requirements/traceability.md#ph-cfg-002).

### Requirement: PH-CFG-003 Перенос шаблонов и настроек стенда

Система SHALL позволять выгрузить выбранные настройки стенда и шаблоны отчётов в JSON и загрузить поддержанный JSON, сообщая результат или ошибку.

#### Scenario: PH-CFG-003-S01 Выбор разделов для выгрузки

- **GIVEN** пользователь выбрал только стенд и шаблоны
- **WHEN** выполнена выгрузка
- **THEN** JSON содержит выбранные разделы; раздел подключений не включён.

#### Scenario: PH-CFG-003-S02 Импорт поддержанных разделов

- **GIVEN** JSON содержит допустимые standConfiguration и reportTemplates
- **WHEN** пользователь загружает файл
- **THEN** разделы сохраняются через соответствующие операции, показывается итог загрузки.

#### Scenario: PH-CFG-003-S03 Неверный формат

- **GIVEN** файл не является допустимым JSON или не содержит поддержанных разделов
- **WHEN** пользователь загружает файл
- **THEN** показывается сообщение об ошибке либо о пропущенных устаревших разделах, успешный импорт не заявляется.

Доказательства и ограничения: [PH-CFG-003](../../../docs/requirements/traceability.md#ph-cfg-003).

### Requirement: PH-CFG-004 Получение фоновых уведомлений

Система SHALL предоставлять сообщения фоновых ошибок с учётом запрошенной области и сохранять сообщения других областей при их чтении.

#### Scenario: PH-CFG-004-S01 Чтение общей области

- **GIVEN** очередь содержит сообщение области load-tests
- **WHEN** прочитана общая область уведомлений
- **THEN** сообщение load-tests остаётся доступно своей области.

#### Scenario: PH-CFG-004-S02 Чтение области тестов

- **GIVEN** очередь содержит global и load-tests сообщения
- **WHEN** прочитана область load-tests
- **THEN** возвращаются сообщения этой области и global; прочитанные сообщения потребляются.

Доказательства и ограничения: [PH-CFG-004](../../../docs/requirements/traceability.md#ph-cfg-004).

### Requirement: PH-CFG-005 Обновление каталога deployment через проверку Grafana

Система SHALL обновлять каталог рендера DropApp и deployment после успешной проверки Grafana, включая сохранение подключения. API SHALL возвращать результат каталога отдельно от доступности Grafana; UI SHALL скрывать успешные READY/EMPTY и показывать ошибки. Каталог SHALL учитывать пользователя, подключение, datasource, namespace и dashboard без изменений настроек и результатов НФТ.

#### Scenario: PH-CFG-005-S01 Проверка и последующий выбор

- **GIVEN** проверка Grafana и чтение метаданных/списка deployment успешны
- **WHEN** пользователь сохраняет подключение либо выполняет его проверку
- **THEN** возвращаются прежние service/success/message и отдельное состояние каталога; конкретные deployment доступны в редакторе шаблона без нового корпоративного запроса при каждом открытии строки.

#### Scenario: PH-CFG-005-S02 Grafana доступна, каталог не обновился

- **GIVEN** проверка доступности успешна, но обновление каталога завершилось ошибкой либо формат не поддержан
- **WHEN** завершается проверка
- **THEN** доступность Grafana остаётся успешной, ошибка каталога видна отдельно; исправные параметры подключения не откатываются по этой причине, последний корректный каталог того же контекста сохранён и помечен устаревшим.

#### Scenario: PH-CFG-005-S03 Успешный пустой список

- **GIVEN** источник корректно вернул пустой список deployment
- **WHEN** обновление завершено
- **THEN** API возвращает EMPTY и время обновления, на странице подключений нет отдельного сообщения каталога; новые deployment выбрать нельзя, прежние строки шаблона не удаляются и не меняются.

#### Scenario: PH-CFG-005-S04 Другой пользователь или контекст

- **GIVEN** сохранён каталог другого пользователя, подключения, datasource, namespace или dashboard
- **WHEN** открыт редактор либо изменены параметры подключения/контекста
- **THEN** чужой каталог не предлагается как актуальный список; обновление не изменяет каталог другого пользователя, а ответ старого контекста не подменяет новый.

#### Scenario: PH-CFG-005-S05 Успех в каждом способе проверки

- **GIVEN** обновление каталога вернуло READY или EMPTY
- **WHEN** проверка запущена для одного источника, для всех подключений либо при сохранении подключения
- **THEN** обычный результат подключения отображается, а строка «Каталог: …», её дата/tooltip и отдельный toast `catalog.message` отсутствуют; при смене прежнего ошибочного результата на успешный прежняя подпись предупреждения удаляется. PARTIAL, STALE, UNAVAILABLE и неизвестный неуспешный статус продолжают отображаться отдельно.

### Requirement: PH-CFG-006 Перенос deployment в шаблонах отчётов

Система SHALL сохранять deployment каждой строки DropApp при экспорте и импорте шаблонов, включая повторения одной панели и их порядок. Прежние файлы с обычными панелями SHALL оставаться допустимыми. Импорт SHALL не подставлять deployment автоматически и не требовать внешнего подключения только для переноса корректно заданного значения.

#### Scenario: PH-CFG-006-S01 Перенос трёх строк

- **GIVEN** экспортированы CPU/profile, CPU/другой deployment и RAM/profile
- **WHEN** файл импортирован в PerfHub и шаблон открыт повторно
- **THEN** восстановлены deployment, пользовательские названия и порядок всех строк; разные deployment одной панели не объединены, служебные идентификаторы строк назначены заново.

#### Scenario: PH-CFG-006-S02 Прежний файл обычных графиков

- **GIVEN** файл старого формата не содержит deployment и описывает обычные панели
- **WHEN** выполнен импорт
- **THEN** сохранено прежнее поведение без обязательных новых полей или обращений к Grafana.

#### Scenario: PH-CFG-006-S03 Некорректная настройка DropApp

- **GIVEN** импортируемая строка явно обозначена как DropApp либо распознана по каталогу и не содержит конкретного deployment или содержит All/список
- **WHEN** импорт сохраняет шаблон, в том числе с отключённой проверкой наличия панели в каталоге
- **THEN** возвращается ошибка настройки строки; отключение проверки наличия панели не отменяет проверку формы deployment. Корректное конкретное значение разрешено переносить без доступного каталога и подтверждается при дальнейшем использовании.

### Requirement: PH-CFG-008 Проверка каталога без рутинной диагностики

Система SHALL не создавать и не обновлять диагностические отчёты каталога Grafana и SHALL не записывать рутинное INFO-резюме проверки. Результат каталога SHALL возвращаться без дополнений о файле/ID проверки. Безопасные WARN фактических отказов каталога SHALL сохраняться. Это требование заменяет автоматическое сохранение, уведомление о файле и fallback при ошибке его записи по ранее применённому PH-CFG-007; остальные правила обновления каталога и выбора deployment сохраняются.

#### Scenario: PH-CFG-008-S01 Отсутствие рутинной записи

- **GIVEN** попытка обновления завершилась любым состоянием каталога
- **WHEN** диагностический сервис публикует результат
- **THEN** он не создаёт INFO-резюме Grafana catalog check/result/updated/failed/globalFailures/omitted; статус, исходное сообщение и время результата сохраняются.

#### Scenario: PH-CFG-008-S02 Сохранение предупреждений

- **GIVEN** произошёл фактический отказ чтения dashboard/deployment, контекста или локального snapshot
- **WHEN** диагностический сервис обрабатывает отказ
- **THEN** соответствующая безопасная WARN-запись содержит этап/категорию/HTTP-код при наличии, не содержит токенов, сырого ответа, URI или stack trace; отсутствие INFO не подавляет другие логи приложения.

#### Scenario: PH-CFG-008-S03 Отсутствие записи и сохранение старых файлов

- **GIVEN** выполняется новая проверка с любым исходом; старый диагностический файл может существовать, а каталог logs может быть недоступен
- **WHEN** формируется результат
- **THEN** сервис не создаёт logs, постоянные или временные отчёты, не изменяет и не удаляет прежние файлы; доступность каталога logs не влияет на исход проверки. Повторный запуск также не пишет отчёт.

#### Scenario: PH-CFG-008-S04 Исходное сообщение и работа deployment

- **GIVEN** проверка возвращает READY, EMPTY, PARTIAL, STALE либо UNAVAILABLE, включая fallback при неожиданном отказе refresh
- **WHEN** результат передаётся в API и UI
- **THEN** поля catalog.status/message/updatedAt и верхнеуровневые service/success/message сохраняют формат; message не дополнено путём отчёта, ID проверки или ошибкой записи файла. Обновление deployment, старые snapshots и ограниченный resources-fallback продолжают работать как прежде.
