# Proposal

## Why

Владелец 23.10.2026 подтвердил фотографиями `Каталог: PARTIAL`, неизвестную применимость CPU-панели DropApp и `GrafanaClientException`. В [клиенте](../../../src/main/java/perfhub/client/GrafanaClient.java) причина API скрывается за общей обёрткой, а [сервис](../../../src/main/java/perfhub/service/GrafanaRenderCatalogService.java) пишет только тип исключения; определить стадию и HTTP-код без отладчика нельзя. Нужен отдельный файл, который владелец сможет прислать после обычной проверки подключения.

## What Changes

- Сохранять читаемый UTF-8 отчёт последней попытки обновления каталога: время, ID проверки, итог, счётчики, этап каждой ошибки, обезличенный ключ дашборда, числовой HTTP-статус при его наличии и фиксированную категорию причины.
- Записывать отчёт автоматически в `logs/grafana-catalog-diagnostics-user-<id>.txt` относительно рабочего каталога процесса. Сообщать расположение в существующем `catalog.message`; при ошибке записи явно сообщать об этом, сохраняя безопасные сведения в консоли через SLF4J.
- Формировать отчёт только из разрешённых полей. Не копировать заголовки, токены, URL, query/selector, значения namespace/deployment, тела ответов, сырые сообщения исключений и stack trace.
- Заменять предыдущий отчёт того же пользователя целиком; ограничить размер и обеспечить целостность при параллельных проверках. Успешная проверка также заменяет прежний ошибочный отчёт.
- Добавить короткую инструкцию: обновить код → запустить обычно → «Подключения / Grafana / Проверить» → прислать указанный файл.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `connection-settings`: добавить PH-CFG-007 — безопасную файловую диагностику каталога Grafana без отладчика; прежний PH-CFG-005 сохраняется.

## Impact

Будущий код: только catalog-методы `GrafanaClient`, `GrafanaRenderCatalogService`, Grafana-ветка fallback в `ConnectionTestService`, небольшие внутренние типы диагностики и компонент записи отчёта. Документы: README, трассировка и реестр. HTTP-схема `service/success/message/catalog` и `catalog.status/updatedAt` сохраняются; `catalog.message` получает указание файла либо ошибки его записи. HTML/CSS/JS, SQL и зависимости не меняются.

Зависимость — уже архивированные `support-dropapp-repeated-panels` и `show-deployment-field-for-all-panels`. От неутверждённых `redact-confluence-credentials`, `isolate-test-environment` и layout-рефакторинга изменение независимо. Общий журнал приложения не выгружается: в нём есть отдельный известный риск G-01.

Вне области: исправление ещё не установленной причины корпоративного API, изменение запроса deployment/selector/прав доступа/repeat, рендер PNG, НФТ, новый API скачивания, импорт G-22 и маскирование прочих интеграций. HTTP-код помогает диагностике, но сам по себе не доказывает конкретную причину отказа.

План согласован владельцем 23.10.2026 отдельным сообщением «согласовано, примени»; Apply и изолированный Verify завершены, см. [проверку](verification.md). Владелец в текущем запросе разрешил commit/push относящегося к задаче результата; разрешение сохранено, но обязательный Review/Apply не отменяет. Archive, merge и deployment не разрешены.
