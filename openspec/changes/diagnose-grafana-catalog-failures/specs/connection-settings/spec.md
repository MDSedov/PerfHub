# Spec Delta

## ADDED Requirements

### Requirement: PH-CFG-007 Диагностический отчёт каталога Grafana

Система SHALL после попытки обновления каталога Grafana автоматически сохранять ограниченный читаемый отчёт с этапом и категорией ошибки, HTTP-статусом при наличии и ID проверки. Пользователь SHALL узнавать расположение файла без отладчика. Отчёт и новые диагностические сообщения SHALL содержать только разрешённые безопасные сведения; отказ записи SHALL не менять результат обновления каталога и проверки подключения.

#### Scenario: PH-CFG-007-S01 Отказ API при загрузке deployment

- **GIVEN** Grafana доступна, а API списка deployment ответил HTTP 400, 401, 403, 404 либо 500
- **WHEN** пользователь выполняет проверку Grafana
- **THEN** отчёт в `logs/grafana-catalog-diagnostics-user-<id>.txt` содержит время, ID проверки, этап получения deployment, обезличенный ключ дашборда, категорию HTTP-ошибки и фактический числовой статус; `catalog.message` указывает расположение файла. Конкретная причина отказа не объявляется установленной только по HTTP-коду.

#### Scenario: PH-CFG-007-S02 Другой этап или отсутствие HTTP-ответа

- **GIVEN** поиск/чтение дашборда завершился ошибкой, транспорт не получил HTTP-ответ либо HTTP 200 содержит пустой/некорректный ответ
- **WHEN** обновление каталога заканчивается
- **THEN** отчёт различает поиск дашбордов, чтение дашборда и получение deployment; содержит фиксированную категорию причины и обозначает отсутствие HTTP-статуса. Если некорректный ответ получен с HTTP 200, код 200 сохраняется, но операция не обозначается успешной.

#### Scenario: PH-CFG-007-S03 Локальный отказ или потеря актуальности

- **GIVEN** каталог не обновлён из-за неподдержанных метаданных, неконкретного datasource/namespace, ошибки локального хранилища или смены контекста во время проверки
- **WHEN** формируется отчёт
- **THEN** указан соответствующий этап и фиксированная категория, отсутствующий HTTP-статус не выдумывается. Смена контекста либо отклонённая публикация snapshot также учитываются как диагностируемая неудача.

#### Scenario: PH-CFG-007-S04 Частичный результат

- **GIVEN** часть дашбордов обновилась, часть завершилась ошибкой
- **WHEN** проверка возвращает PARTIAL
- **THEN** отчёт содержит итог и счётчики успешных/неуспешных дашбордов с отдельными записями ошибок; доступность Grafana остаётся успешной. Прежние правила сохранения актуального/устаревшего каталога, НФТ и выбора deployment не изменяются.

#### Scenario: PH-CFG-007-S05 Повторная и успешная проверка

- **GIVEN** для пользователя сохранён предыдущий диагностический отчёт
- **WHEN** очередная проверка завершается, в том числе READY или EMPTY
- **THEN** её новый целостный отчёт заменяет предыдущий файл этого пользователя, содержит новый ID проверки и не выдаёт прежние ошибки за текущие. Открытие шаблона не создаёт новый отчёт и не вызывает Grafana.

#### Scenario: PH-CFG-007-S06 Запись файла недоступна

- **GIVEN** каталог `logs` недоступен для записи либо замена файла завершилась ошибкой
- **WHEN** завершается проверка
- **THEN** её исходные success и состояние каталога сохраняются; `catalog.message` явно сообщает, что отчёт этой проверки сохранить не удалось. Безопасные сведения с ID проверки доступны в консоли; старый файл не объявляется результатом новой проверки.

#### Scenario: PH-CFG-007-S07 Секреты и недоверенные сообщения

- **GIVEN** HTTP-заголовки, URI, selector, исключение либо тело ошибочного ответа содержат синтетический секрет, персональные значения, управляющие символы или инструкции
- **WHEN** формируются файл, новые диагностические сообщения консоли и дополнение к `catalog.message`
- **THEN** ни эти данные, ни сырой stack trace не попадают в них. Разрешены только сгенерированные ID/время, числовые счётчики/HTTP-код, обезличенный ключ дашборда, известные системе этапы/категории и заранее заданные пояснения.

#### Scenario: PH-CFG-007-S08 Пользователи, параллельность и размер

- **GIVEN** проверки выполняются параллельно либо число ошибок превышает предел отчёта
- **WHEN** сохраняются результаты
- **THEN** разные пользователи получают разные файлы; попытки одного пользователя не смешивают строки. Сохраняется один целостный отчёт завершившейся проверки, не более 100 записей ошибок и 128 КиБ; пропущенные записи учтены отдельным счётчиком. Отчёт хранится локально без нового API чтения/скачивания.

#### Scenario: PH-CFG-007-S09 Совместимость без дополнительных запросов

- **GIVEN** выполняются прежние операции проверки подключения, обновления каталога и рендера обычных/DropApp-панелей
- **WHEN** включена диагностика
- **THEN** последовательность и параметры корпоративных HTTP-запросов, retry/timeout, формулы, snapshot/НФТ, JSON-схема и верхнеуровневые service/success/message сохраняются. Меняется только диагностическое содержание `catalog.message`; новый файл не является доказательством исправления исходного корпоративного отказа.
