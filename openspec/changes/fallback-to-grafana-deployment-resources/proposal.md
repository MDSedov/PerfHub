# Proposal

## Why

Отчёт владельца 23.10.2026 подтвердил: восемь дашбордов обновились, один завершился ошибкой `DEPLOYMENT_VALUES / HTTP_ERROR / HTTP 404`, deployment не получены. [PerfHub](../../../src/main/java/perfhub/client/GrafanaClient.java) использует datasource proxy, тогда как [Prometheus-клиент Grafana 13.0.1](https://github.com/grafana/grafana/blob/v13.0.1/packages/grafana-prometheus/src/datasource.ts#L314-L343) читает metadata через datasource resources; нужен ограниченный путь совместимости после 404, сохраняющий уже работающие подключения.

## What Changes

- Сохранить существующий запрос deployment через proxy основным.
- Только после HTTP 404 этого запроса один раз вызвать соответствующий resources endpoint с теми же UID datasource, selector, GET и авторизацией.
- Успешный resources-ответ обработать по прежним правилам списка deployment и позволить обновить каталог. Успешный пустой ответ остаётся EMPTY.
- При ошибке дополнительного запроса сохранить его фактический статус и отдельный безопасный этап в уже существующем диагностическом файле. Не возвращать пустой список вместо ошибки.
- Для всех остальных ошибок первого запроса сохранить прежний отказ без второго обращения. Не перебирать datasource, URL и варианты query.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `grafana-visualization`: добавить PH-GRAF-010 — один альтернативный запрос ресурсов того же datasource только после proxy HTTP 404.

## Impact

Планируемая область: catalog-метод GrafanaClient и внутренний этап GrafanaCatalogDiagnostic, клиентские/service-тесты, трассировка и реестр. Изменяется последовательность внешних чтений **только** для proxy 404: вместо одного запроса допустимы два. Это намеренное функциональное изменение, не рефакторинг и не обычная сетевая retry-политика. Таймаут каждого запроса, авторизация, DTO/URL PerfHub, snapshots, рендер/кеш/НФТ, HTML/CSS/JS, SQL и зависимости сохраняются.

Зависимости: архивированный support-dropapp-repeated-panels и уже применённый/опубликованный `diagnose-grafana-catalog-failures` (727d9c6). Диагностическое изменение завершено, но не архивировано: его утверждённые артефакты не переписываются; PH-CFG-007 не переносится напрямую в основные specs.

**D:** 404 не устанавливает, что именно отсутствует: proxy-маршрут, datasource/plugin или ресурс upstream. Нативный маршрут подтверждён исходниками Grafana, но его доступность на корпоративном стенде ещё не проверена. Патч устраняет конкретное ограничение совместимости, не гарантирует устранение любой причины 404.

Вне области: автоматический поиск/замена UID по имени, перечисление источников, прямой доступ к Prometheus/VM, изменение selector, новые форматы query, временные окна, лимиты, права доступа и общие логи. При двух ошибках диагностика остаётся явной. Откат — возврат клиентского метода и нового внутреннего этапа без изменения данных.

Review и Apply получены 23.10.2026: владелец ответил «согласовано, примени fallback-to-grafana-deployment-resources» после представления всех четырёх артефактов. Прежнее разрешение владельца на commit/push относящегося результата сохраняется; Archive/merge/deployment не разрешены. Согласование разрешает реализацию PH-GRAF-010, но не является доказательством корпоративной совместимости.
