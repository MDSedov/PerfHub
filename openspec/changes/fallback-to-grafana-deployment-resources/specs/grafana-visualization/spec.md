# Spec Delta

## ADDED Requirements

### Requirement: PH-GRAF-010 Совместимое получение deployment через ресурсы datasource

Система SHALL после HTTP 404 основного proxy-запроса списка deployment однократно запросить тот же список через resources API того же datasource. При другом исходе основного запроса дополнительное обращение SHALL отсутствовать. Ошибка resources SHALL сохраняться как явный отказ с безопасным этапом и фактическим HTTP-кодом при наличии; прежний выбор и контекст каталога SHALL сохраняться.

#### Scenario: PH-GRAF-010-S01 Успех дополнительного маршрута

- **GIVEN** основной GET списка deployment через datasource proxy вернул HTTP 404
- **WHEN** GET `/api/datasources/uid/{uid}/resources/api/v1/label/deployment/values` вернул корректный Prometheus-ответ `status: success` с непустым строковым массивом `data`
- **THEN** выполнены ровно два запроса списка с теми же базовым URL, UID datasource, буквальным selector в `match[]` и авторизацией; варианты deployment обработаны прежними правилами фильтрации, удаления дублей и сортировки. При отсутствии других ошибок каталог обновлён без PARTIAL из-за обработанного proxy 404.

#### Scenario: PH-GRAF-010-S02 Работающий основной маршрут

- **GIVEN** основной proxy-запрос вернул корректный успешный ответ, в том числе пустой `data`
- **WHEN** формируется список deployment
- **THEN** используется этот ответ и выполнен ровно один запрос списка; resources API не вызывается, текущий выбор deployment не подставляется вместо пустого ответа.

#### Scenario: PH-GRAF-010-S03 Другие ошибки основного запроса

- **GIVEN** основной запрос вернул HTTP 400, 401, 403, 429 либо 5xx, завершился транспортной ошибкой или получил пустой/некорректный HTTP 200
- **WHEN** обновляется каталог
- **THEN** resources API не вызывается; сохраняются прежние отказ, диагностический этап и фактический HTTP-код либо его отсутствие. Ошибки поиска и чтения dashboard также не запускают дополнительный запрос deployment.

#### Scenario: PH-GRAF-010-S04 Ошибка дополнительного маршрута

- **GIVEN** после основного HTTP 404 resources-запрос завершился HTTP-ошибкой, транспортным отказом либо пустым/некорректным ответом
- **WHEN** завершается обновление каталога
- **THEN** третий запрос списка не выполняется; неуспешный dashboard учитывается один раз, прежний snapshot сохраняется по действующим правилам. В существующем диагностическом файле указан `DEPLOYMENT_VALUES_RESOURCES`, категория окончательного отказа и фактический код resources-ответа, в том числе 200 при ошибке формата, либо отсутствие кода при транспортном отказе. Ошибка не превращается в успешный пустой список.

#### Scenario: PH-GRAF-010-S05 Успешный пустой дополнительный ответ

- **GIVEN** после основного HTTP 404 resources API вернул `status: success` и пустой строковый массив `data`
- **WHEN** проверка завершается без других ошибок и другие dashboard не дали вариантов deployment
- **THEN** результат каталога — EMPTY с актуальным пустым списком; обработанный 404 не записывается как текущий отказ. Исторический выбор не удаляется и не выдаётся за полученный вариант.

#### Scenario: PH-GRAF-010-S06 Безопасная диагностика обоих маршрутов

- **GIVEN** недоверенные URI, заголовки, selector, тело ответа или исключение содержат синтетический секрет либо управляющие символы
- **WHEN** формируются файл, новые сообщения консоли и `catalog.message`
- **THEN** сохраняется разрешённый состав диагностических сведений PH-CFG-007 без сырых URI, заголовков, selector, тела и stack trace; новый этап является фиксированной константой. Формат файла, путь и ограничения размера не меняются.

#### Scenario: PH-GRAF-010-S07 Сохранение границ контекста и чтения

- **GIVEN** каталог обновляется для конкретного пользователя, подключения, datasource и namespace либо пользователь читает сохранённый каталог/редактор шаблона
- **WHEN** доступен дополнительный маршрут
- **THEN** он используется только в прежней операции обновления, с прежними проверками владельца, revision и актуальности перед публикацией snapshot. Чтение локального каталога не вызывает Grafana; иной datasource/namespace не подбирается. Рендер обычных/DropApp-панелей, кеш изображений, НФТ и HTTP/JSON-контракты PerfHub сохраняются.
