# Design

## Context

Мотивация и границы — [proposal](proposal.md); контракт — [PH-GRAF-010](specs/grafana-visualization/spec.md). Изменение намеренно меняет внешнюю последовательность чтений только для одного HTTP-исхода.

- **A, код:** [GrafanaClient.loadDeploymentLabelValues](../../../src/main/java/perfhub/client/GrafanaClient.java) всегда вызывает `/api/datasources/proxy/uid/{uid}/api/v1/label/deployment/values` с `match[]`. `readCatalogJson` различает HTTP/транспорт/некорректный ответ и сохраняет фактический статус.
- **A, код:** [GrafanaRenderCatalogService](../../../src/main/java/perfhub/service/GrafanaRenderCatalogService.java) разрешает datasource/namespace, фильтрует варианты, проверяет owner/revision/контекст и сохраняет snapshot. Типизированная клиентская ошибка уже переопределяет диагностический этап. Локальное чтение не обновляет источник.
- **A, наблюдение владельца 23.10.2026:** новый файл показывает восемь обновлённых dashboard, один отказ `DEPLOYMENT_VALUES / HTTP_ERROR / 404` и ноль вариантов. Это устанавливает этап и статус, не первопричину. Содержимое общего журнала и реальные идентификаторы сюда не переносятся.
- **A, первичный источник:** [metadataRequest Grafana 13.0.1](https://github.com/grafana/grafana/blob/v13.0.1/packages/grafana-prometheus/src/datasource.ts#L314-L343) использует `/api/datasources/uid/{uid}/resources`; [language provider](https://github.com/grafana/grafana/blob/v13.0.1/packages/grafana-prometheus/src/language_provider.ts#L117-L120) извлекает `res.data.data`, то есть сохраняется Prometheus envelope. [Документация Grafana](https://grafana.com/docs/grafana/latest/developer-resources/api-reference/http-api/api-legacy/data_source/) также описывает UID proxy; считать его заведомо неверным для всех установок нельзя.
- **C:** единственный маршрут не использует resources-совместимость; один отказ блокирует snapshot подходящего dashboard, что объясняет отсутствие подтверждённой применимости в редакторе.
- **D:** какой компонент вернул корпоративный 404 и поможет ли resources на данном стенде. [Обработчик UID proxy Grafana](https://github.com/grafana/grafana/blob/v13.0.1/pkg/services/datasourceproxy/datasourceproxy.go) допускает 404 при ненайденных datasource/plugin; ответ upstream также может быть ошибкой. Автоматическая замена UID по имени доказательствами не обоснована.

## Goals / Non-Goals

**Goals:** ограничить дополнительное чтение одним вызовом и сделать окончательный отказ различимым по этапу без расширения диагностических данных. Решение остаётся внутри транспортного клиента и существующей цепочки catalog service → client.

**Non-Goals:** определение UID через новые API, подбор другого источника, изменение query/selector, запросы напрямую к Prometheus/VM, POST, временные окна и лимиты Grafana, новые настройки/UI. Версия Java, данные, HTML/CSS/JS, зависимости и сборка вне области.

## Decisions

### 1. Дополнительный маршрут только после HTTP 404 получения deployment

Основной proxy GET остаётся прежним. В `loadDeploymentLabelValues` перехватывается только типизированный `HTTP_ERROR` с кодом 404 первого чтения. Выполняется один GET:

`/api/datasources/uid/{uid}/resources/api/v1/label/deployment/values?match[]=...`

Префикс настроенного base URL, UID, буквальный selector, bearer и таймаут остаются прежними. URL строится существующим `UriComponentsBuilder`; тест проверяет декодированное значение `match[]`, включая `$`, `+`, пробелы и специальные символы. Не добавляются цикл, повтор resources, перебор UID и обратный переход к proxy. На 401/403/429/5xx, транспорт и ошибки формата переход отсутствует. Ошибки поиска/загрузки dashboard эту ветку не запускают.

Альтернативы: заменить proxy повсеместно — риск для работающих установок; повторять при любой ошибке — лишние запросы при отказе прав/таймаутах; подбирать UID по имени — отдельное поведение без подтверждения причины. Выбранная ветка сохраняет успешный основной маршрут и ограничивает цену проверки совместимости.

### 2. Единый строгий разбор ответа с этапом выбранного маршрута

Оба ответа проходят прежнюю проверку `status == success`, `data` — массив строк. Каталожные фильтрация/дедупликация/сортировка остаются в сервисе. Пустой массив успешен; пустое тело, не-JSON и неправильная структура — ошибка. При разборе передаётся фактический этап: `DEPLOYMENT_VALUES` либо новая константа `DEPLOYMENT_VALUES_RESOURCES` в [GrafanaCatalogDiagnostic.Stage](../../../src/main/java/perfhub/dto/grafana/GrafanaCatalogDiagnostic.java). Сохраняется фактический HTTP-код, в том числе 200 при некорректном теле, либо null без HTTP-ответа.

Альтернатива — считать пустой/неподдержанный ответ отсутствием deployment — скрывает отказ и потому исключена. Разбор в сервисе потребовал бы переноса транспортного контракта через слой и не нужен.

### 3. Учитывать итог операции dashboard

Если resources успешен, обработанный proxy 404 не увеличивает счётчик неуспешных dashboard. Если resources неуспешен, существующий перехват учитывает dashboard один раз и пишет окончательную типизированную ошибку. Схема файла, JSON PerfHub, лимиты 100 записей/128 КиБ и безопасная запись отчёта сохраняются; новые поля, URI и тела не добавляются.

Ранее согласованный PH-CFG-007 описывает диагностику, которая сама не создаёт запросов. Его S09 не является разрешением новой последовательности: её отдельно задаёт PH-GRAF-010. При окончательном 404 требования PH-CFG-007 к статусу и этапу сохраняются; успешно обработанный промежуточный 404 не объявляется текущим отказом. Артефакты завершённой диагностики не переписываются.

## Risks / Trade-offs

- **Другая причина 404** → оба маршрута могут отказать; отчёт сохраняет окончательный этап/код, исправление UID или прав требует отдельного обоснования.
- **Дополнительная задержка при proxy 404** → максимум один дополнительный запрос с прежним таймаутом; остальные исходы без дополнительных обращений.
- **Различия плагина/формата ответа** → строгий прежний Prometheus envelope; неподдержанный ответ не публикует пустой успешный snapshot.
- **Смена контекста между запросами** → прежние service/repository проверки остаются обязательными; дополнительный запрос не разрешает публикацию устаревшего результата.
- **Утечка из второго исключения** → только прежний allowlist и фиксированный новый этап; тест с синтетическими секретами во всех недоверенных частях.

## Regression Matrix

| Проверка | Основание / способ после Apply |
|---|---|
| PH-GRAF-010-S01/S02/S05 | MockRestServiceServer: proxy 404 → resources 200; основной 200 → один запрос; пустые ответы; точный порядок, UID, GET, auth, base prefix и selector. Service + изолированная H2: READY/EMPTY и варианты |
| PH-GRAF-010-S03/S04 | HTTP 400/401/403/429/500, timeout, invalid JSON/структура/пустое тело для основного; HTTP 404/403/500, timeout и invalid 200 для resources; отсутствие третьего вызова; счётчики, PARTIAL/STALE/UNAVAILABLE и старый snapshot |
| PH-GRAF-010-S06 | Реальный клиент → service → файл: конечный этап/код; синтетические секреты отсутствуют в новых логах/файле/catalog.message; отказ записи не меняет итог |
| PH-GRAF-010-S07 | Существующие owner/revision/context/late-publication и локальное чтение; дополнительно смена контекста после resources; renderer/cache/НФТ/ordinary contracts и JS проверки без правок |
| Безопасность и границы | Относящиеся тесты и полный `mvn test` только во временной копии pom/src/config с проверенной относительной H2 и JDK 17; пользовательские БД/кеши/экспорты не копировать. Корпоративные API не вызывать |

UI не меняется: новый browser/UI-проход не является условием этой транспортной ветки. Проверка Maven не объявляется доказательством корпоративной совместимости; последующая проверка владельцем выполняется прежней кнопкой Grafana и создаёт тот же диагностический файл.

## Migration Plan

После Review и отдельного Apply реализовать ограниченную ветку, затем тесты/Verify и обновить трассировку фактическими результатами. Миграций данных, очистки каталога, изменения настроек и production-конфигурации нет. Откат — возврат клиентской ветки и внутренней константы к предыдущей версии без удаления snapshot или диагностических файлов. Git результата разрешён прежней командой владельца после Verify; Archive/merge/deployment требуют отдельной команды.
