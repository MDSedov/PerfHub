### C/D — проблема и неподтверждённое

Владелец сообщил об отсутствии поля после локального запуска, импорта и discover. Условное создание поля подтверждено кодом; почему именно его панель не получила scope, не установлено. Нельзя объявить любой dashboard с deployment подходящим или считать локальный запуск причиной. Корпоративные интеграции/БД не исследуются; дополнительные фотографии для проектирования этого UI не нужны.

## Goals / Non-Goals

**Goals:** постоянная колонка и понятное состояние каждого поля; одиночный выбор; сохранность модели при disabled/перерисовке; различение неприменимости и неизвестных метаданных.

**Non-Goals:** изменение текущего правила пригодности панелей по PH-GRAF-006/007, поддержка новых формул/форматов/repeat, получение данных через discover НФТ, изменение импорта подключений, сохранения/рендера/кеша/размера графиков, НФТ, DDL и зависимостей. Наличие переменной у dashboard само по себе не означает, что общая панель фильтруется по ней.

## Decisions

### 1. Отдельная постоянная колонка

Порядок: «Порядок», «Название графика», «Код графика», «Deployment», «Удалить». Создавать select для каждой строки, а не только внутри ветки scope. Пустая таблица использует colspan=5. Сохранить существующие ID контейнеров/кнопок и `chartDeployment-<index>`; для каждой строки связать label/aria-label и текст причины через aria-describedby. Обновить только зависящие от числа колонок CSS-селекторы, если они есть; общий каскад/sidebar/ресурсы не переносить.

Уточнение владельца 22.10.2026 перед Archive/Git: убрать комментарии под полем. Текст пояснения остаётся визуально скрытым для `aria-describedby` и доступен при наведении через `title` ячейки/поля. Состояние видно в самом select; для STALE его варианты дополнены «список устарел», чтобы явное предупреждение сохранилось без подписи снизу. Значения и правила выбора не меняются; PH-REP-010 сохраняется.

Альтернатива — оставлять поле под кодом, но не скрывать. Отклонена: отдельная колонка соответствует ожидаемому владельцем месту и делает заблокированное состояние заметным.

### 2. Применимость вычисляется сервером из текущего локального каталога

Добавить к элементу прежнего массива GET `/api/settings/confluence-templates/panel-options` необязательное поле `deploymentApplicability`:

- `SUPPORTED`: панель подтверждена как deploymentScoped действующим нормализатором;
- `NOT_APPLICABLE`: соответствующая панель есть в корректном snapshot того же контекста и не поддерживает выбор deployment;
- `UNKNOWN`: соответствующего snapshot/панели нет либо метаданные не подтверждены.

Использовать уже хранящиеся панели snapshot и существующие catalogStatus/updatedAt. Обогащать обычные варианты только если они уже доступны через прежний lookup; не предлагать дополнительные обычные панели из snapshot. Для неподходящей панели не вычислять scope по имени dashboard, title или текстовому наличию слова deployment. Отсутствие snapshot не превращать в NOT_APPLICABLE. Stale сопровождать предупреждением, не заявлять свежесть данных.

Изменения ограничены service record, DTO и его mapping controller. Новые URL, SQL, таблицы, запросы Grafana, фоновые задачи и правки parser/client не нужны. Старые клиенты игнорируют дополнительное поле; новый UI при его отсутствии использует прежний подтверждённый renderScope для supported, иначе UNKNOWN. Поле состояния не сохраняется в строке и не входит в export/import/render/cache.

Альтернативы: только `renderScope == null` как «неприменимо» — скрывает ошибку данных; анализ формул браузером — дублирует нормализатор и неверно трактует зависимости pod/container. Обе отклонены.

### 3. Состояния видимого select

| Состояние строки | Поле и объяснение |
|---|---|
| Панель не выбрана | Disabled, «Сначала выберите график». |
| NOT_APPLICABLE | Disabled, «Не применяется» и объяснение, что график не поддерживает выбор deployment. Для stale пояснить, что это сохранённые метаданные. |
| UNKNOWN / нет вариантов из-за недоступности | Disabled, «Каталог недоступен» / «Применимость не определена»; подсказка проверить только подключение Grafana. Существующее значение видно, но не заменяется. |
| SUPPORTED, READY, варианты есть | Обычный single-select, пустая подсказка и конкретные значения; без multiple/All/free text/автовыбора первого. |
| SUPPORTED, STALE, варианты есть | Single-select доступен, видимое предупреждение о последнем сохранённом списке; текущая семантика stale сохраняется. |
| SUPPORTED, успешный EMPTY | Disabled, «Нет доступных deployment»; историческое значение показано отдельно как сохранённое. Ошибка получения и успешный пустой список различаются. |
| Есть только сохранённое исчезнувшее значение | Оно видно, select заблокирован за отсутствием актуальных альтернатив. Если актуальные альтернативы имеются, single-select доступен с сохранённым значением и пометкой его отсутствия в каталоге. |

Обновление вариантов происходит существующим чтением panel-options при загрузке страницы. В этой работе не добавлять polling, новый запрос к Grafana при открытии строки или автоматическое восстановление подключения. Ошибка самого GET должна оставлять строки/значения видимыми с недоступным состоянием и прежним уведомлением.

### 4. Модель строки остаётся источником сохранения

HTML disabled не должен приводить к пропуску deployment: payload по-прежнему строится из draft. Открытие, повторный render, движение строки и недоступность каталога не очищают значения. Только явная смена панели выполняет уже существующий сброс scope/deployment; после выбора другой подходящей панели требуется новый явный выбор. Обычная строка сохраняется без нового обязательного параметра; прежние серверные проверки конкретного значения, scope и исторического выбора сохраняются.

## Risks / Trade-offs

- Пятая колонка сужает таблицу → проверить 992/993 px, ширину select/кнопок, внутреннюю прокрутку modal/table, label и доступность клавиатурой.
- UNKNOWN можно принять за отсутствие переменной → отдельное значение DTO и отдельная подсказка; не маскировать ошибку словом «Неприменимо».
- Disabled может потерять сохранённое значение → проверять реальные save payload/reopen и смешанные строки, а не только наличие HTML disabled.
- Старый snapshot может не отражать текущую формулу → показывать stale, не расширять применимость по догадке; обновление остаётся явной проверкой подключения.
- Новое поле само по себе не исправляет корпоративное получение каталога → явно сохраняется D; до установления причины не менять query/reference/parser.

Проверки будущего Apply: релевантные Java-тесты состояния локального каталога и совместимости DTO, действующие JS-контракты сохранения, браузер с настоящим DOM и синтетическими API-ответами для всех состояний. Без новых зависимостей проекта. Полный Maven только из безопасной временной копии с новым относительным H2 и JDK 17 по AGENTS.md; пользовательские БД/кеш/экспорты не копировать. Для UI изолированный стенд без корпоративных подключений. Реальный renderer повторно не требуется, пока рендер-код не меняется; существующее покрытие рендера сохраняется.

## Migration Plan

1. Review proposal/delta/design/tasks и отдельная команда Apply. До этого — только планирование.
2. Аддитивное метаданное panel-options и UI одной таблицы, без DDL/преобразования данных; проверить матрицу и обновить уровни доказательств.
3. При откате вернуть UI и DTO/service в прежнюю версию; сохранённые deployment/scope остаются в прежнем формате, данные и кеш не удалять. Корпоративное развёртывание, archive и Git — отдельные команды.

## Open Questions

Блокирующих продуктовых вопросов для этого UI нет. Граница поддерживаемых панелей закреплена в Non-Goals и сохраняет PH-GRAF-006/007. Причина недоступности метаданных в корпоративном случае остаётся D и не нужна для проектирования постоянного поля; задача импорта G-22 рассматривается отдельно.
