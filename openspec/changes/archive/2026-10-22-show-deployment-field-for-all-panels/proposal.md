# Proposal

## Why

Сейчас редактор скрывает Deployment, если у выбранной панели нет `renderScope=DROPAPP_DEPLOYMENT`. Пользователь видит обычную строку и не может отличить неприменимый выбор от недоступных метаданных. Владелец запросил постоянно видимое поле: заблокированное для неподходящих графиков и одиночный список для подходящих.

## What Changes

- Всегда показывать отдельную колонку **Deployment** между «Код графика» и «Удалить» во всех шаблонах отчётов. После добавления строки поле остаётся видимым при любом выборе панели.
- Для подтверждённо неподходящего графика блокировать поле и объяснять неприменимость. До выбора графика показывать «Сначала выберите график».
- Для подходящей панели разрешать выбрать ровно один конкретный deployment из локального каталога. Режим всех pod/container и отсутствие All deployment сохраняются.
- Отдельно показывать неизвестную применимость/недоступный каталог, успешный пустой список и устаревший список. Отсутствие метаданных не объявлять отсутствием переменной.
- Сохранять существующее значение, порядок, перенос и обычные строки при открытии/перерисовке. Менять deployment только явным выбором пользователя либо очищать при явной смене панели согласно нынешнему поведению.

Статус: **Review получен 22.10.2026**, владелец явно разрешил Apply: «согласовано, примени show-deployment-field-for-all-panels». Реализация и изолированные проверки — в [Verify](verification.md). Исходный AS-IS, риск и неподтверждённые причины корпоративного случая разделены в [design](design.md).

## Capabilities

### New Capabilities

Нет: используется существующая область шаблонов.

### Modified Capabilities

- `reporting-publication`: PH-REP-010, постоянное поле Deployment с явными состояниями и одиночным выбором. PH-REP-008/009 сохраняются.

## Impact

Планируются изменения `settings-templates.html`, при необходимости узких CSS таблицы и аддитивных метаданных `panel-options` в существующих service/controller/DTO. Обычный каталог не расширяется неподтверждёнными панелями; открытие редактора не обращается к Grafana. Новый статус вычисляется по текущему локальному snapshot, без новой таблицы/миграции.

Java 17, Spring MVC, Thymeleaf, Bootstrap 5, Vanilla JavaScript, Maven и версии зависимостей сохраняются. URL, авторизация, save/export/import, рендер, reference, PNG-кеш, названия/порядок изображений, общие размеры и НФТ не меняются. Зависимость — уже архивированный `support-dropapp-repeated-panels`; остальные открытые планы не затрагиваются.

Вне области: новые правила определения подходящих графиков/новые форматы Grafana, универсальные панели без repeat, редактирование PromQL, получение deployment из произвольных формул, автоматический refresh, изменение импорта подключений и диагностика корпоративной Grafana. Исправление скрытого результата каталога при импорте остаётся отдельным пробелом G-22. Отсутствие поля у владельца не доказывает конкретную ошибку источника.
