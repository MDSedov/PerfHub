# Proposal

Архивировано 22.10.2026 штатным CLI по отдельной команде владельца; основные specs обновлены (+8 требований / +33 сценария), Verify завершён.

## Why

По сообщению владельца корпоративный PerfHub уже успешно рендерит графики в разделе «Выгрузить графики». Требуется дополнить этот рабочий путь для DropApp: его dashboard содержит повторяемую по `deployment` строку и usage/request/limit, а шаблон пока не позволяет задать deployment каждой строке ([исследование](design.md#context)).

## What Changes

- В «Настройки → Шаблоны отчётов → Графики отчёта» для подходящих графиков DropApp требовать **один конкретный deployment**. По уточнению владельца от 21.10.2026 выбора «Все deployment», конкретного pod и нескольких deployment в одной строке не будет: все pod выбранного deployment отображаются в одном PNG.
- Разрешить отдельные строки одной базовой панели для разных deployment; сохранить порядок шаблона и различимые названия изображений в интерфейсе и Confluence. Например: CPU/profile, CPU/другой deployment, RAM/profile — три изображения.
- Получать отдельный каталог метаданных рендера и доступных deployment через Grafana при сохранении/проверке её подключения; различать доступность Grafana и результат обновления каталога. Не использовать обновление каталога НФТ для этого действия.
- Использовать работающий каталог обычных панелей; дополнить только получение метаданных DropApp из подтверждённых Classic либо `elements`/`variables`/`RowsLayout` представлений и связь с повторяемой строкой. Не заменять общий механизм обнаружения и не выдавать динамические копии за самостоятельные сохранённые panelId.
- Рендерить выбранную базовую панель с deployment конкретной строки и разрешением всех её pod/container средствами Grafana 13.0.1, указанной владельцем. Внешняя ссылка может адресовать экземпляр repeat: на новом фото подтверждён `panelId=profile$panel-106`; числовой базовый ID в шаблоне сохраняется. Уточнить транспортную ссылку, идентификацию строки, ключи кеша и перенос настроек.
- Использовать существующие общие `image-width`/`image-height`; целевой размер по уточнению владельца — **1000×1000** вместо используемых им 1000×500. Проверить PNG, кеш и пропорции изображения в отчёте, а также читаемость полной легенды на согласованном примере DropApp. Новые переменные размера, индивидуальные размеры строк и жёсткий override для DropApp не вводить; настройки в текущем проходе не изменять.
- Сохранить обычные панели без repeat и прежние шаблоны таких панелей. Для прежних строк, распознанных как DropApp, потребовать явный deployment вместо подстановки случайного значения.

## Capabilities

### New Capabilities

Нет: используются существующие области требований.

### Modified Capabilities

- `grafana-visualization`: каталог рендера DropApp, одна панель за deployment, идентификация строки/кеш, совместимость и ошибки — PH-GRAF-006…009.
- `reporting-publication`: deployment в строке шаблона и упорядоченные изображения в отчёте — PH-REP-008…009.
- `connection-settings`: обновление каталога при проверке Grafana и перенос расширенного шаблона — PH-CFG-005…006.

## Impact

Будущая реализация затронет Grafana client/service/cache, настройки и DTO шаблонов, Grafana-ветку проверки подключения, `settings-templates.html`, `settings-connections.html`, `settings.html`, `grafana-panels.html`, `tests.html`, узкое формирование заголовков графиков Confluence и существующие JDBC-репозитории. Предлагаются только добавочные поля/таблицы существующей H2; их назначение и откат описаны в design. В Apply добавлены согласованные nullable-колонки и таблицы каталога, код и проверки. Зависимости и production-конфигурация не изменены; Verify завершён на изолированном стенде 22.10.2026; корпоративные условия не проверялись.

Java 17, Spring Boot/MVC, Thymeleaf, Bootstrap 5, Vanilla JavaScript и Maven сохраняются с версиями `pom.xml`. URL и существующие обязательные поля API сохраняются; дополнительные необязательные поля описаны в design. Работающие транспорт рендера, настроенный render-path, построение маршрута, авторизация, получение PNG, slug fallback, retry/timeout и обычные панели переиспользуются. Фото UID-only ссылки Grafana само по себе не является основанием менять рабочий маршрут PerfHub: точечно меняются контекст переменных и значение panel reference для DropApp.

Вне объёма: изменение Grafana dashboard/PromQL, произвольный движок template variables, все deployment в одной строке, выбор pod/container, дополнительные изображения из repeat, правила/пороги/статусы/временные окна НФТ, общий рефакторинг и глобальная политика кешей. Панели без подтверждённой фильтрации по deployment не объявляются подходящими автоматически по названию dashboard.

Зависимости: проверка конкретного формата API/ссылки рендера и цепочки переменных по фотографиям либо на отдельном разрешённом стенде; безопасная среда тестов — после `isolate-test-environment` или проверенная временная копия по AGENTS.md. Другие открытые change сохраняются; согласования layout/logging не подразумеваются. Регрессионная матрица и ограничения доказательств — в design; трассировка и решения — в `docs/requirements/`. Отдельный Apply уже получен. Archive/sync и записывающие Git-операции требуют отдельных команд.
