### C/D — ограничения выводов

- **C:** при получении нового формата как пустого старый discover способен очистить панельный/переменный каталог и снять выбор. Доказано устройством parser + sync, но такой корпоративный инцидент не воспроизводился.
- **D:** фото JSON-модели не доказывает формат `/api/dashboards/uid`: API может конвертировать модель. Нужны читаемые фрагменты фактического ответа либо отдельный разрешённый тестовый стенд; новые endpoint по фотографиям не выдумываются.
- **A/D:** версия Grafana 13.0.1 теперь сообщена владельцем; успешный запрос одного scoped-экземпляра и его All-маркеры видны в DevTools. Возможность заменить `profile$panel-106` на голое `106`/`panel-106`, другие deployment/панели, версия renderer и историческая полнота не подтверждены. Не считать прежнюю гипотезу о numeric solo достаточной.
- **C:** некоторые запросы на фото не содержат namespace напрямую. Передача var-namespace не исправляет исходный PromQL. Полнота/правильность самого dashboard и его limits/requests вне этой работы; недостающие серии PerfHub не создаёт.

## Goals / Non-Goals

**Goals:** добавить настройки одной строки без множителя PNG; изолировать контекст рендера от НФТ; сохранить обычный путь; заранее получить значения deployment, а не считать `current` полным списком. Нормативные сценарии — в [Grafana](specs/grafana-visualization/spec.md), [отчётах](specs/reporting-publication/spec.md), [подключениях](specs/connection-settings/spec.md).

Работающий корпоративный раздел «Выгрузить графики» — исходная база по сообщению владельца. Предложение не переустанавливает renderer, не перестраивает общий PNG-пайплайн и не заменяет его маршрут/авторизацию по фотографии браузерного запроса. Изменения ограничиваются настройкой и получением правильных DropApp-изображений в этом пути и связанном шаблоне/отчёте.

**Non-Goals:** весь универсальный движок переменных Grafana, парсинг/переписывание произвольного PromQL, новый frontend/build, полная миграция старых общих кешей, исправление корпоративных метрик. В новой постановке отдельный каталог pod для UI не нужен: pod/container разрешает Grafana при рендере. Старый `renderSelectedPanels` без строк современного шаблона и legacy hierarchy не расширяются новым выбором deployment.

## Decisions

### 1. Базовая панель с контекстом строки

Выбран вариант: одна сохранённая строка → одна выбранная базовая панель → одна подтверждённая транспортная ссылка её deployment-экземпляра → один PNG. В каталоге, шаблоне и внешних DTO PerfHub базовый panelId остаётся числовым. Внутренний `renderPanelRef` отделён от него: на новом фото для базовой панели 106 успешен **`profile$panel-106`**, а не доказан голый numeric ID. Это использование адреса одного экземпляра repeat, без перечисления копий и без умножения изображений.

Для Grafana 13.0.1 узкое дополнение существующего клиента должно воспроизвести подтверждённый scoped reference по deployment строки, element reference и layout; `profile` не зашивается в код. Наблюдённая форма `<deployment>$panel-<id>` — эталон для проверки соответствующего layout, а не универсальное правило всех Grafana/вложенных repeat. Неизвестная структура не преобразуется по догадке. URL на фото содержит `/render/d-solo/<uid>` без slug, но PerfHub уже работает со своим настроенным маршрутом: **маршрут не меняется на UID-only без отдельного доказательства необходимости**. Переиспользовать имеющееся построение URI, авторизацию и PNG validation, добавив внутреннее строковое reference для DropApp. Базовый numeric overload обычных панелей и существующий fallback slug сохраняются. Входные данные пользователя не используются как произвольный URL/reference.

Контекст копируется для каждой строки: настроенные datasource/namespace и прочие разрешённые переменные, поверх них **один deployment строки**, затем pod/container в All. Общие настройки не обновляются. All означает все значения зависимых переменных dashboard для этого deployment; список pod не фиксируется по снимку подключения и не используется как фильтр исторического периода.

В транспортном адаптере отделить внутреннее представление All от URL. На успешном запросе владельца переданы **`var-pod=$__all` и `var-container=$__all`**; использовать эту подтверждённую форму для данного адаптера, а не подменять её документированным для других случаев `All`, литералом `.*`, запятой, первым pod или отсутствующей переменной. Строковые reference и значения query кодируются как значения URL. Подтвердить на изолированном renderer два deployment и всю зависимую цепочку; одно фото не доказывает полноту всех pod в каждом периоде. Если исходная цепочка не ограничивает pod выбранным deployment, поддержка такой панели не считается проверенной.

CPU/RAM/Request/Limit берутся из сохранённых Grafana queries и vizConfig; PerfHub не рассчитывает ряды и не переносит request/limit в thresholds. Панель подходит, если принадлежит строке repeat по deployment и её запросы зависят от deployment прямо либо через подтверждённую цепочку pod/container. Общие ALL/NETWORK-панели не получают фиктивный фильтр. Распознавание — по метаданным и зависимостям, не по одному отображаемому имени dashboard или списку захардкоженных ID.

| Альтернатива | Оценка |
|---|---|
| Передать несколько deployment и положиться на repeat Grafana | Полезно для полного dashboard, но не соответствует принятой одной строке/одному deployment. Не выбрано. |
| Перечислить все динамические копии и рендерить их | Расширяет число PNG и ломает существующее сопоставление отчёта. Не выбрано. Scoped reference единственного выбранного deployment используется адресно, как на новом фото. |
| Отрисовать целый dashboard/row одним изображением | Смешивает выбранные метрики и строки, меняет масштаб/порядок отчёта. Не выбрано. |

### 2. Отдельные метаданные изображений

Добавить небольшой компонент каталога рендера и нормализатор в существующем клиентском слое. Он читает доступные dashboard через Grafana, различает Classic и подтверждённый новый формат; сохраняет базовый числовой panelId, element reference, заголовок/описание, принадлежность строке и зависимости переменных, контекст получения renderPanelRef, datasource/namespace и fingerprint определения панели. Поддержанные envelope/форматы проверяются до замены snapshot; неизвестный формат даёт явную ошибку. Rows не превращаются в графики. Читаются все нужные queries для применимости, а не только первый.

Каталог не вызывает `GrafanaDashboardSettingsService.pullFromGrafana`, не записывает `panel_query`, `panel_threshold`, `is_test_query`, не запускает НФТ и не меняет `GrafanaVariableService.applyVariables`, используемый НФТ/VM. Старый явный discover настроек НФТ не перерабатывается в этом change. Для редактора шаблона объединить локальные обычные panel-options с render-options: совпавший dashboardUid/panelId имеет одну запись с дополнительной возможностью deployment, строки шаблона при этом не дедуплицируются.

Новая scoped-строка проверяет наличие панели и загружает контекст/slug/метаданные из render-каталога, а не требует предварительного заполнения старых `grafana_dashboard_panels` и `grafana_dashboards` через discover НФТ. Обычная строка сохраняет нынешние repository/context lookup. Иначе пользователь был бы вынужден выполнить запрещённое для этого сценария обновление query/threshold ради получения изображения.

### 3. Предварительная загрузка deployment

После успешного `checkHealth` в Grafana-ветке проверки обновить метаданные и конкретные deployment для текущих datasource/namespace. Сохранение подключения уже вызывает эту проверку. Повторная кнопка проверки служит ручным обновлением, scheduler/фоновый polling не добавляются. GET panel-options и открытие строки читают локальный snapshot.

Пустые `options` на фото не являются списком значений. Узкий Prometheus-адаптер выполняет поддержанную форму query переменной deployment через Grafana datasource API в контексте настроенных datasource/namespace; читает query и regex из определения, не восстанавливает их по названию метрики/фото. Не отправлять `label_values(...)` как обычный PromQL. Поддержать только реально подтверждённую форму этой переменной; неизвестная query/regex — явная ошибка каталога. Прямой доступ к Prometheus/VM/DropApp не нужен. Встроенные current/options годятся как метаданные, но не как полный каталог. All исключается из списка, значения сохраняются отдельно от текста, порядок UI детерминирован по тексту/значению.

Новые запросы каталога разрешены только в проверке/сохранении Grafana: health, поиск и чтение dashboard, разрешение datasource и deployment по уникальному контексту. Запросы каталога pod/container не добавляются. Рендер переиспользует существующий PNG-запрос/маршрут и fallback slug, добавляя только scoped reference и переменные DropApp; при ошибке numeric/reference варианты не перебираются вслепую. Интерполяцию pod/container выполняет renderer. Ни просмотр шаблонов, ни cacheOnly не инициируют корпоративные запросы. Остальные параметры браузерной ссылки (например, refresh/hideLogo/orgId) не копируются автоматически как обязательная новая конфигурация.

Ответ проверки сохраняет `service/success/message`; добавить необязательный объект `catalog` с `status`, `updatedAt`, безопасным `message`. Состояния: READY, EMPTY, STALE, UNAVAILABLE; при нескольких dashboard допускается агрегат PARTIAL с отдельными состояниями. Ошибка каталога после успешного health не меняет `success=true`: UI показывает предупреждение и не откатывает исправные credentials. Ошибка health сохраняет прежний `success=false` и не запускает обновление. Корректный пустой ответ — EMPTY, не STALE.

Snapshot обновляется атомарно для контекста dashboard. Ошибка оставляет последний корректный snapshot этого же контекста; старые значения показаны как устаревшие и не маскируют ошибку. При EMPTY старые строки шаблона сохраняются. Смена datasource/namespace/подключения инвалидирует актуальность списка; запоздавший ответ старого контекста не публикуется в новом.

### 4. Строка шаблона, API и идентификация

Добавить nullable `render_scope` и `deployment` к `confluence_report_template_charts`. Scope `DROPAPP_DEPLOYMENT` фиксирует назначение строки даже без сети; null сохраняет прежний обычный формат. По каталогу scope подтверждает сервер; неизвестный scope отклоняется. Новая/изменённая настройка требует конкретное значение из доступного snapshot; существующее исчезнувшее значение можно сохранить без изменения и запросить за исторический период. Устаревший доступный snapshot явно обозначается. Свободный ввод, All, массив и пустое значение не принимаются.

Уже существующие строки не заполняются dashboard current. Если каталог распознал старую строку как подходящую DropApp, отсутствие deployment блокирует её сохранение/рендер с указанием строки. До подключения каталога обычные панели сохраняют старую семантику; неизвестные новые панели не объявляются подтверждёнными DropApp.

Использовать существующий `ConfluenceTemplateChart.id` как `templateChartId`, связанный с сохранённой версией шаблона. Repository сейчас пересоздаёт строки при save: после сохранения UI получает свежие id. Это не вечный внешний ID, не основа ключа PNG и не переносимое поле export. Устаревший/чужой id даёт ошибку и предложение перечитать шаблон.

| Контракт | Добавочное изменение |
|---|---|
| Save/read/export/import шаблона | Необязательные `renderScope`, `deployment`; read дополнительно возвращает `templateChartId`. При обычных строках scope/deployment не требуются. Import проверяет форму значений даже при `validateCharts=false`, но не обращается к Grafana ради переноса. |
| GET `/api/settings/confluence-templates/panel-options` | Дополнительные renderScope, список deployment и состояние/время локального snapshot для подходящих панелей. |
| POST `/api/grafana/panels/range/panel` | Необязательный `templateChartId`; остаются templateId/dashboardUid/panelId/from/to. Проверяется принадлежность строки и совпадение панели. При разных deployment старый неоднозначный запрос возвращает 400, при однозначном сохраняет работу. Значение deployment всегда берётся из шаблона, не из произвольного override запроса. |
| Ответ PNG/набора | Необязательные templateChartId/deployment позволяют сопоставить результат строке; templateChartOrder передаёт порядок строки между группами dashboard. Существующие обязательные поля и группировка dashboard сохраняются; UI восстанавливает порядок шаблона по строкам и не полагается на порядок групп dashboard. |
| Проверка подключения | Добавочный catalog; Grafana health success/message и поведение остальных сервисов сохранены. |

Авторизация/роли и URL не меняются. Новые ошибки конфигурации используют существующий 400/message, ошибки Grafana — существующий 502/message; причины безопасны, без заголовков и тел интеграций.

### 5. Размеры, кеш и названия

Использовать уже существующие общие `image-width` и `image-height`: владелец выбрал **1000×1000**, увеличив высоту с используемых им 500 до 1000 для легенды DropApp. Это значение настроек, не новая константа, не индивидуальный размер типа/строки и не новая переменная. Поскольку настройки общие, они применяются и к обычным графикам. Их дальнейшее ручное изменение сохраняет существующую семантику; значение в БД/production-конфигурации в этой работе не записывается.

Код уже читает эти параметры для рендера, кеша и разметки Confluence; реализация должна сохранить этот единый источник. В браузере и отчёте не сжимать квадратный PNG до пропорций 1000×500 и не обрезать его. Переход 1000×500 → 1000×1000 — отдельная регрессия кеша. На тестовом dashboard с согласованным набором pod/container проверить полную легенду CPU/RAM при 1000×1000; размер сам по себе не гарантирует, что легенда любого числа серий поместится. При обнаруженном обрезании зафиксировать результат и согласовать дальнейшее решение, не менять размеры/макет Grafana автоматически.

Существующие тест/template/panel/period/размеры остаются частью ключа. Для DropApp сериализовать отдельный версионированный контекст: активный пользователь/идентичность источника, revision подключения, datasource, namespace, fingerprint панели, выбранный deployment, renderPanelRef и версия правила его получения, разрешённые переменные и стратегия All. Внутренние поля контекста не отправляются как фиктивные var-параметры. Ревизия подключения — служебный идентификатор, обновляемый при изменении base-url/api-key/render-path Grafana; секреты и их копии в каталоге не сохраняются.

Использовать существующий столбец `variables_hash` и файловое именование для хеша нового контекста, не менять ключи обычных панелей. Первый scoped-запрос не использует старое нескоупленное PNG. `templateChartId` не входит в ключ: одинаковые параметры двух строк могут переиспользовать байты, но обе строки остаются в результате со своими названиями. Range без testUuid по-прежнему не получает постоянный кеш. forceRefresh/cacheOnly сохраняются; ошибки не кешируются, cacheOnly не читает метаданные из сети.

В браузере tests при каждом повторном открытии выполнять новый локальный cacheOnly: прежний HTML/ответ или in-flight запрос по одному testId не считается подтверждением актуальных строк. Так смена deployment/порядка проверяется сервером; новых запросов к Grafana cacheOnly не делает. Результат одиночного range применяется к templateChartId; поздний ответ прошлого запуска не переносится в новую строку. Общий singleton-кеш последнего ответа не становится источником выбора строки или контекста другого запроса.

Отображаемый заголовок scoped-строки: пользовательское название плюс `[deployment: значение]`. Формирование едино для UI, create report и append; обычный chart.title сохраняет прежний путь. Поля экранируются как текст. Имена вложений могут сохранить существующий случайный UUID: не вводится новая идемпотентность публикации. Связь строка → PNG → attachment явная, имя вложения не используется как ключ deployment.

### 6. Ошибки и пустые результаты

Невыбранный deployment, неизвестный формат/неразрешимые datasource/namespace/All — явная ошибка настройки, без подстановки current/первого значения. Корректное «No data» PNG от Grafana допустимо; по PNG нельзя достоверно отличить отсутствие отдельных серий. Дополнительные метрические запросы для проверки НФТ/наличия limit не вводятся.

Сохранить существующее различие операций: браузер периода продолжает по строкам с локальной ошибкой; bulk/test возвращает ошибку при сбое строки, уже сохранённые корректные PNG остаются в кеше. Для создания/append сначала подготовить все обязательные PNG, затем выполнять внешнюю запись; число изображений равно числу строк. Частичные ошибки уже начатой внешней публикации, retry и отсутствие общего rollback не исправляются и не объявляются атомарными.

### 7. Границы кода, UI и хранения

- Java: клиент — транспорт и разбор подтверждённых моделей, небольшой сервис — каталог/контекст рендера, сервис шаблонов — проверки строки, repository — SQL. Не переносить все пакеты и не включать HTTP в новые DB-транзакции. Существующие records, constructor injection и final-зависимости сохраняются.
- HTML/JS: deployment-select только у подходящей строки, нет pod-select и «Все deployment». Сохранить существующие ID, формы, drag-and-drop, modal, sidebar, порядок ресурсов и тип скриптов. Новые ARIA labels связываются с уникальной строкой. Название deployment не используется как HTML/DOM id. Inline JS не переносится массово; ES-модули не вводятся.
- CSS: только необходимая раскладка поля редактора и перенос отдельного статуса каталога подключения; без изменения общей темы/каскада/sidebar.
- H2: два nullable столбца chart плюс отдельный snapshot-каталог JSON/CLOB с user/connection/context и служебной revision источника. Имена новых таблиц уточняются в реализации; существующие таблицы query/threshold и пользовательские данные не преобразуются. Не хранить headers/tokens и полные экспорты подключений. В текущем проходе схема не меняется.

## Risks / Trade-offs

| Риск C/D | Мера и граница |
|---|---|
| Реальный API/envelope/renderer отличается от фото | До изменения production-кода подтвердить конкретные поля и solo-render на обезличенном fixture и локальном изолированном renderer. Нет подтверждения — остановить соответствующую задачу, не добавлять произвольный endpoint/запрос. |
| All dependent pod остаётся связанным с прежним deployment | Проверка двух deployment с непересекающимися pod/container, включая общий сохранённый одиночный pod. Нельзя принимать только наличие PNG как доказательство правильной фильтрации. |
| Каталог только текущего состояния, pod живут недолго | Не сохранять текущий список pod как фильтр исторического запроса. Сохранённый исчезнувший deployment не подменяется; историческая полнота зависит от Grafana/источника и явно не доказана. |
| НФТ связаны с прежним discover/сервисом переменных (G-10) | Отдельный render-каталог; регрессия неизменности SQL/query/threshold/статусов и числа вызовов НФТ/VM. |

| Рост времени проверки | Загрузка только deployment по уникальному контексту, без перечней всех pod и фонового polling; UI показывает отдельный результат каталога. Общие timeout/retry не изменяются. |

| Runtime reference отличается от базового ID | Эталон `profile$panel-106` отделён от числового 106; проверить CPU/RAM и другой deployment для Grafana 13.0.1. Не требовать смены panelId-колонок/HTTP DTO на строку и не считать numeric URL проверенным. |
| Необычные кавычки deployment Definition | Сохранить наблюдение как текст, проверить фактическую query/запрос datasource; не исправлять PromQL dashboard в рамках этого change. Ошибка загрузки списка не маскируется current. |
| Высота 1000 не вместила все строки легенды | Визуально проверить согласованный пример при 1000×1000; не обещать неограниченную легенду и не менять размер/панель самовольно. |
| Старый save/экспорт теряет новые поля | Сквозной create/edit/reorder/export/import тест, включая `validateCharts=false` и старый формат. |
| Пустое тело renderer отличается от корректного No data PNG | Первый случай — ошибка без записи кеша; второй — исходное PNG, без анализа метрик и выдуманных рядов. |

## Migration Plan

1. Review владельца proposal/трёх delta/design/tasks и отдельный запрос Apply. CLI ready/done не является согласованием.
2. Снять технические ограничения по API/renderer/variable query на обезличенных данных. Фото допустимы, файл из корпоративной среды не требуется. Если подтверждение требует изменить требования/границы, сначала обновить и повторно согласовать change.
3. В безопасной среде закрепить обычные контракты и новые сценарии, затем добавить nullable-поля и snapshot-хранилище без преобразования прежних данных; проверить идемпотентность DDL на чистой и прежней синтетической схеме.
4. Подключить каталог, строку шаблона, перенос, рендер и кеш; проверить матрицу. Никаких производственных миграций/обращений в рамках подготовки или тестов.
5. Возможное развёртывание — отдельная команда владельца после Verify. При откате до использования scoped-строк вернуть прежнюю версию, оставить добавочные данные. После использования scoped-строк простой запуск старой версии опасен: она проигнорирует deployment и при save потеряет настройки. Перед таким откатом остановить операции с затронутыми шаблонами и восстановить их из подготовленного до миграции резервного состояния либо убрать scoped-строки по отдельному решению владельца; подтвердить обычные графики. Не удалять таблицы/файлы/данные автоматически. Snapshot и кеш нового контекста можно перестать использовать без удаления. Применение и любые восстановительные операции не разрешены этим предложением.

## Open Questions

Продуктовых блокирующих вопросов по количеству deployment/pod/PNG и порядку больше нет: последнее уточнение владельца заменило прежние варианты «Все deployment» и выбора pod; размер 1000×1000 задан через существующие общие настройки. Версию Grafana и успешную CPU PNG-ссылку для profile владелец уже предоставил — повторно их запрашивать не требуется. Ниже оставшиеся D для точного адаптера и приёмки; они не разрешают изменение согласованных границ.

- Фактический API подтверждён новыми фото: meta/dashboard, Classic panels/templating.list, row 135 repeat deployment, qryType=1, пустой regex, multi/includeAll=true, allValue отсутствует. Необычный selector сохраняется буквально; Label values разбирается в label API. Повторно просить JSON/фото этого фрагмента не требуется. Корпоративные datasource-права и семантика selector агентом не проверялись.
- Изолированный Grafana 13.0.1 с renderer v5.12.8 проверил рабочий маршрут PerfHub, CPU двух deployment, RAM, зависимые All pod/container, PNG 1000×1000 и другой общий размер. Корпоративная версия renderer и история удалённых pod неизвестны; вложенные repeat не поддерживаются по догадке.
- Легенда 27/18 синтетических серий CPU/RAM помещается в 1000×1000; произвольная длина имён и число серий не гарантируются. Корректный No data PNG проверен, отсутствие отдельных реальных request/limit по изображению автоматически не оценивается.
- Перестановка, успешное сохранение и повторное открытие подтверждены владельцем; функция перестановки, API и JDBC проверены отдельно. Финальный UI Verify 7.1 завершён через разрешённый владельцем Playwright после ошибок CUA; повторное согласование продуктового объёма не потребовалось. Штатный Bootstrap bundle блокируется прежней SRI-ошибкой, fallback проверен. Блокирующих локальных проверок нет; дальнейшие корпоративные проверки и развёртывание не входят в этот Apply.
