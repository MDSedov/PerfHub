# Доступ и пользователи

## Purpose

Обеспечить пользователям вход в PerfHub, доступ к разрешённым разделам и управление учётными записями в пределах роли.

Статус: baseline официально согласован владельцем 12.10.2026. Зафиксирован существующий AS-IS; уровни доказательств сохранены. Спорные вопросы остаются в реестре, без изменения функций, статусов, временных интервалов и источников порогов НФТ.

## ADDED Requirements

### Requirement: PH-AUTH-001 Вход по учётной записи

Система SHALL предоставлять вход активному пользователю по логину и паролю и отклонять неверные учётные данные.

#### Scenario: PH-AUTH-001-S01 Успешный вход

- **GIVEN** существует активная учётная запись
- **WHEN** пользователь отправляет правильный пароль и допустимый локальный redirect
- **THEN** создаётся авторизованная сессия и возвращается перенаправление на указанный адрес; без допустимого адреса — на /main.

#### Scenario: PH-AUTH-001-S02 Неверные данные

- **GIVEN** пароль неверен либо активная запись не найдена
- **WHEN** отправлена форма входа
- **THEN** отображается форма с сообщением об ошибке; доступ от имени указанного пользователя не предоставляется.

Доказательства и ограничения: [PH-AUTH-001](../../../../../../docs/requirements/traceability.md#ph-auth-001).

### Requirement: PH-AUTH-002 Защита разделов и административных операций

Система SHALL разрешать защищённые операции только активному авторизованному пользователю, а административные — только роли ADMIN.

#### Scenario: PH-AUTH-002-S01 Гость обращается к защищённому ресурсу

- **GIVEN** авторизованной сессии нет
- **WHEN** запрошен /tests либо /api/tests
- **THEN** HTML-запрос перенаправляется на /login с адресом возврата; API возвращает 401 и сообщение.

#### Scenario: PH-AUTH-002-S02 Недостаточно прав

- **GIVEN** пользователь имеет роль USER
- **WHEN** запрошен /api/admin/users либо /admin/users
- **THEN** доступ отклоняется с 403.

#### Scenario: PH-AUTH-002-S03 Учётная запись удалена

- **GIVEN** сессия ссылается на более не активного пользователя
- **WHEN** выполняется защищённый запрос
- **THEN** сессия перестаёт давать доступ; запрос обрабатывается как запрос гостя.

Доказательства и ограничения: [PH-AUTH-002](../../../../../../docs/requirements/traceability.md#ph-auth-002).

### Requirement: PH-AUTH-003 Завершение сессии

Система SHALL завершать текущую сессию по действию выхода и возвращать пользователя к форме входа.

#### Scenario: PH-AUTH-003-S01 Выход из активной сессии

- **GIVEN** пользователь вошёл
- **WHEN** отправлен POST /logout
- **THEN** текущая сессия инвалидируется и возвращается redirect /login.

#### Scenario: PH-AUTH-003-S02 Выход без сессии

- **GIVEN** сессии нет
- **WHEN** отправлен POST /logout
- **THEN** возвращается redirect /login без создания авторизованной сессии.

Доказательства и ограничения: [PH-AUTH-003](../../../../../../docs/requirements/traceability.md#ph-auth-003).

### Requirement: PH-AUTH-004 Администрирование пользователей

Система SHALL позволять администратору просматривать активных пользователей, создавать и редактировать их данные и роли, а также удалять обычную учётную запись из активного списка.

#### Scenario: PH-AUTH-004-S01 Создание пользователя

- **GIVEN** администратор задал уникальный логин, имя, допустимую роль и совпадающие непустые пароли
- **WHEN** создаётся пользователь с пустой фамилией
- **THEN** учётная запись создаётся; фамилия остаётся пустой; ответ не содержит пароль или его хеш.

#### Scenario: PH-AUTH-004-S02 Недопустимые данные

- **GIVEN** указан уже занятый активный логин или пароли не совпадают
- **WHEN** администратор сохраняет пользователя
- **THEN** операция отклоняется с сообщением об ошибке.

#### Scenario: PH-AUTH-004-S03 Удаление обычной записи

- **GIVEN** существует обычная активная запись, не защищённая bootstrap-правилом
- **WHEN** администратор удаляет её
- **THEN** она отсутствует в активном списке и не может войти.

Доказательства и ограничения: [PH-AUTH-004](../../../../../../docs/requirements/traceability.md#ph-auth-004).

### Requirement: PH-AUTH-005 Изменение собственного профиля

Система SHALL позволять пользователю просматривать и изменять собственные имя, фамилию, логин и пароль без изменения своей роли через профиль.

#### Scenario: PH-AUTH-005-S01 Сохранение без смены пароля

- **GIVEN** пользователь вошёл и отправил допустимые данные профиля с пустым новым паролем
- **WHEN** профиль сохранён
- **THEN** обновляются данные профиля, прежний пароль и роль сохраняются.

#### Scenario: PH-AUTH-005-S02 Новый пароль не подтверждён

- **GIVEN** пользователь задал разные новый пароль и подтверждение
- **WHEN** отправлены данные профиля
- **THEN** изменение отклоняется с сообщением об ошибке.

Доказательства и ограничения: [PH-AUTH-005](../../../../../../docs/requirements/traceability.md#ph-auth-005).

### Requirement: PH-AUTH-006 Навигация по доступным возможностям

Система SHALL предоставлять авторизованному пользователю переходы к тестам и отчётам, графикам, конфигурациям стенда, настройкам и профилю; административные пункты SHALL отображаться только администратору.

#### Scenario: PH-AUTH-006-S01 Обычный пользователь

- **GIVEN** вошёл пользователь USER
- **WHEN** открывается страница с общим меню
- **THEN** доступны основные разделы и профиль, административное меню скрыто.

#### Scenario: PH-AUTH-006-S02 Администратор

- **GIVEN** вошёл пользователь ADMIN
- **WHEN** открывается общее меню
- **THEN** дополнительно доступны пользователи и типы тестов; переход ведёт в соответствующий раздел.

Доказательства и ограничения: [PH-AUTH-006](../../../../../../docs/requirements/traceability.md#ph-auth-006).
