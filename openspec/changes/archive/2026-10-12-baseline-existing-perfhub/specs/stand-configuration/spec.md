# Конфигурация нагрузочного стенда

## Purpose

Позволить зафиксировать состав нагрузочного стенда, сопоставить его с тестом и получить сохранённые сведения без изменения внешних ресурсов.

Статус: baseline официально согласован владельцем 12.10.2026. Зафиксирован существующий AS-IS; уровни доказательств сохранены. Спорные вопросы остаются в реестре, без изменения функций, статусов, временных интервалов и источников порогов НФТ.

## ADDED Requirements

### Requirement: PH-STAND-001 Выбор состава стенда

Система SHALL предоставлять и сохранять выбор namespace, компонентов и сервисов для захвата конфигурации стенда.

#### Scenario: PH-STAND-001-S01 Выбраны ресурсы

- **GIVEN** доступны namespace и сервисы
- **WHEN** пользователь сохраняет выбранный состав
- **THEN** при чтении настроек возвращается сохранённый выбор; захват использует выбранные ресурсы.

#### Scenario: PH-STAND-001-S02 Список namespace недоступен

- **GIVEN** DropApp не вернул список, но настроенные namespace непусты
- **WHEN** пользователь получает варианты namespace
- **THEN** возвращаются настроенные namespace как резервный список.

Доказательства и ограничения: [PH-STAND-001](../../../../../../docs/requirements/traceability.md#ph-stand-001).

### Requirement: PH-STAND-002 Просмотр текущей конфигурации

Система SHALL возвращать текущие ресурсы выбранных namespace с доступными версиями, релизом и характеристиками ресурсов, объединяя эквивалентные pod для представления.

#### Scenario: PH-STAND-002-S01 Явно выбран namespace

- **GIVEN** DropApp вернул ресурсы выбранного namespace
- **WHEN** запрошена текущая конфигурация
- **THEN** ответ содержит выбранные namespace, сгруппированные элементы и максимальный обнаруженный релиз.

#### Scenario: PH-STAND-002-S02 Релиз не указан в ресурсах

- **GIVEN** есть версии контейнеров, но отсутствуют релизные метки
- **WHEN** формируется представление конфигурации
- **THEN** версия контейнера не используется как выдуманный релиз.

Доказательства и ограничения: [PH-STAND-002](../../../../../../docs/requirements/traceability.md#ph-stand-002).

### Requirement: PH-STAND-003 Сохранение снимка стенда

Система SHALL сохранять непустую конфигурацию как отдельный снимок с составом ресурсов, метаданными и доступными документами; при найденной связи Jira SHALL включать её в сведения снимка.

#### Scenario: PH-STAND-003-S01 Захват выполнен

- **GIVEN** выбраны ресурсы, DropApp вернул непустую конфигурацию
- **WHEN** пользователь запускает захват
- **THEN** создаётся снимок с идентификатором, временем, ресурсами и доступными документами; найденная Jira-ссылка включается в ответ.

#### Scenario: PH-STAND-003-S02 Нет ресурсов

- **GIVEN** выбор не дал элементов конфигурации
- **WHEN** запрошен захват либо сохранение пустого набора
- **THEN** операция отклоняется с 400 без выдачи успешного снимка.

Доказательства и ограничения: [PH-STAND-003](../../../../../../docs/requirements/traceability.md#ph-stand-003).

### Requirement: PH-STAND-004 Работа с сохранёнными снимками

Система SHALL предоставлять список и детали снимков, позволять изменять релиз и комментарий и удалять выбранный снимок.

#### Scenario: PH-STAND-004-S01 Метаданные изменены

- **GIVEN** снимок существует
- **WHEN** сохранены новый релиз и комментарий
- **THEN** ответ и повторное чтение содержат обновлённые сведения.

#### Scenario: PH-STAND-004-S02 Удаление

- **GIVEN** снимок существует
- **WHEN** пользователь удаляет снимок
- **THEN** он исчезает из списка; последующий запрос его деталей получает 404.

#### Scenario: PH-STAND-004-S03 Неизвестный снимок

- **GIVEN** передан отсутствующий ID
- **WHEN** запрошены детали, обновление или удаление
- **THEN** возвращается 404.

Доказательства и ограничения: [PH-STAND-004](../../../../../../docs/requirements/traceability.md#ph-stand-004).

### Requirement: PH-STAND-005 Архив конфигурации

Система SHALL позволять скачать ZIP сохранённой конфигурации с информацией о снимке, таблицей ресурсов и имеющимися документами.

#### Scenario: PH-STAND-005-S01 Скачивание снимка

- **GIVEN** снимок содержит ресурсы и сохранённые документы
- **WHEN** запрошен архив
- **THEN** ответ application/zip имеет имя вложения и содержит snapshot-info.txt, resources.csv и сохранённые документы; доступные дистрибутивы включаются отдельно.

#### Scenario: PH-STAND-005-S02 Архив отсутствующей конфигурации

- **GIVEN** снимка либо снимка указанного теста нет
- **WHEN** запрошен архив
- **THEN** возвращается 404 вместо пустого успешного архива.

Доказательства и ограничения: [PH-STAND-005](../../../../../../docs/requirements/traceability.md#ph-stand-005).

### Requirement: PH-STAND-006 Конфигурация выбранного теста

Система SHALL предоставлять сохранённую конфигурацию теста и позволять повторно захватить актуальный состав стенда для этого теста.

#### Scenario: PH-STAND-006-S01 Повторный захват

- **GIVEN** тест существует, выбранный стенд вернул непустую конфигурацию
- **WHEN** пользователь запрашивает захват для теста
- **THEN** последующее получение конфигурации теста возвращает новый снимок.

#### Scenario: PH-STAND-006-S02 Прежние сведения

- **GIVEN** для теста нет нового снимка, но сохранены строки прежнего формата конфигурации
- **WHEN** запрошены детали конфигурации
- **THEN** возвращается представление имеющихся строк; наличие нового снимка не выдумывается.

Доказательства и ограничения: [PH-STAND-006](../../../../../../docs/requirements/traceability.md#ph-stand-006).
