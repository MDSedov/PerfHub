# Подключения и пользовательские настройки

## Purpose

Позволить настроить внешние подключения PerfHub, проверить их доступность и перенести поддержанные настройки с явным результатом операции.

Статус: baseline официально согласован владельцем 12.10.2026. Зафиксирован существующий AS-IS; уровни доказательств сохранены. Спорные вопросы остаются в реестре, без изменения функций, статусов, временных интервалов и источников порогов НФТ.

## ADDED Requirements

### Requirement: PH-CFG-001 Персональные настройки подключений

Система SHALL читать и сохранять параметры шести поддержанных подключений в контексте текущего пользователя; изменение персонального значения одного пользователя SHALL не изменять уже сохранённое персональное значение другого.

#### Scenario: PH-CFG-001-S01 Разные пользователи

- **GIVEN** у двух пользователей сохранены разные значения одного параметра подключения
- **WHEN** каждый запрашивает свои настройки
- **THEN** каждый получает своё значение.

#### Scenario: PH-CFG-001-S02 Изменение параметра

- **GIVEN** пользователь вошёл и передал service/key/value подключения
- **WHEN** параметр сохранён
- **THEN** повторное чтение этим пользователем возвращает новое значение; существующая персональная запись другого пользователя не изменяется.

Доказательства и ограничения: [PH-CFG-001](../../../../../../docs/requirements/traceability.md#ph-cfg-001).

### Requirement: PH-CFG-002 Проверка подключения

Система SHALL позволять запросить проверку поддержанного подключения и возвращать идентификатор сервиса, признак успеха и сообщение о результате.

#### Scenario: PH-CFG-002-S01 Подключение доступно

- **GIVEN** для выбранного сервиса заданы настройки и проверочный запрос успешен
- **WHEN** пользователь выполняет проверку
- **THEN** возвращаются service, success=true и сообщение.

#### Scenario: PH-CFG-002-S02 Сервис недоступен или не поддержан

- **GIVEN** проверочный запрос завершился ошибкой либо имя сервиса не поддерживается
- **WHEN** выполнена проверка
- **THEN** возвращаются success=false и сообщение; успешное подключение не заявляется.

Доказательства и ограничения: [PH-CFG-002](../../../../../../docs/requirements/traceability.md#ph-cfg-002).

### Requirement: PH-CFG-003 Перенос шаблонов и настроек стенда

Система SHALL позволять выгрузить выбранные настройки стенда и шаблоны отчётов в JSON и загрузить поддержанный JSON, сообщая результат или ошибку.

#### Scenario: PH-CFG-003-S01 Выбор разделов для выгрузки

- **GIVEN** пользователь выбрал только стенд и шаблоны
- **WHEN** выполнена выгрузка
- **THEN** JSON содержит выбранные разделы; раздел подключений не включён.

#### Scenario: PH-CFG-003-S02 Импорт поддержанных разделов

- **GIVEN** JSON содержит допустимые standConfiguration и reportTemplates
- **WHEN** пользователь загружает файл
- **THEN** разделы сохраняются через соответствующие операции, показывается итог загрузки.

#### Scenario: PH-CFG-003-S03 Неверный формат

- **GIVEN** файл не является допустимым JSON или не содержит поддержанных разделов
- **WHEN** пользователь загружает файл
- **THEN** показывается сообщение об ошибке либо о пропущенных устаревших разделах, успешный импорт не заявляется.

Доказательства и ограничения: [PH-CFG-003](../../../../../../docs/requirements/traceability.md#ph-cfg-003).

### Requirement: PH-CFG-004 Получение фоновых уведомлений

Система SHALL предоставлять сообщения фоновых ошибок с учётом запрошенной области и сохранять сообщения других областей при их чтении.

#### Scenario: PH-CFG-004-S01 Чтение общей области

- **GIVEN** очередь содержит сообщение области load-tests
- **WHEN** прочитана общая область уведомлений
- **THEN** сообщение load-tests остаётся доступно своей области.

#### Scenario: PH-CFG-004-S02 Чтение области тестов

- **GIVEN** очередь содержит global и load-tests сообщения
- **WHEN** прочитана область load-tests
- **THEN** возвращаются сообщения этой области и global; прочитанные сообщения потребляются.

Доказательства и ограничения: [PH-CFG-004](../../../../../../docs/requirements/traceability.md#ph-cfg-004).
