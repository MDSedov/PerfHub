# Design

## Context

Review/Apply получены 26.10.2026 с уточнением об отключении файла. Ветка work; предшествующее расследование UID и документы proposal сохранены. Владелец подтвердил корпоративный сценарий deployment после исправления сохранённой переменной; собственные проверки агента используют синтетику.

Сейчас testConnection показывает catalog.message, renderConnectionsTable создаёт подпись каталога, publish пишет INFO/WARN и файл. Обновление deployment и данные API от этого вывода не зависят.

## Goals / Non-Goals

**Goals:** убрать успешные сообщения READY/EMPTY, INFO-резюме и автоматическую запись диагностических файлов; сохранить ошибки и рабочее обновление каталога.

**Non-Goals:** удаление старых файлов, отключение WARN, изменение API shape/HTTP/SQL/стека/зависимостей, новые флаги или изменения Grafana. Archive, Git и deployment отдельно не разрешены.

## Decisions

1. В двух существующих JS-ветках (toast/подпись) проверять точные READY/EMPTY. Остальные состояния, включая unknown, остаются предупреждениями; catalog сохраняется в connectionStatuses. Обычные уведомления подключения и null-catalog работают как прежде.
2. Удалить из диагностического сервиса INFO и файловый writer/render, работу с путями/временными файлами, зависимость CurrentUserProvider, нужную только для имени отчёта. Сохранить типизированные безопасные WARN ошибок. publish возвращает исходный GrafanaCatalogResult без дополнения message; его внутренний контракт с сервисом каталога остаётся. unavailable возвращает прежний UNAVAILABLE и безопасно фиксирует реальный отказ.
3. Старые отчёты не очищаются. Операции файловой системы для диагностики полностью отсутствуют, поэтому I/O-отказ каталога logs больше не является новым событием. Остальные логи приложения не подавляются глобальным logging.level.
4. PH-CFG-005 меняется через delta. Новый PH-CFG-008 отменяет файловое поведение применённого PH-CFG-007. Исторический согласованный delta и baseline не переписываются; при будущем штатном Archive учитывать порядок этих изменений. PH-GRAF-010 и sequence HTTP не меняются.

Альтернативы: оставить writer отключённым флагом — лишняя настройка и риск повторной записи; удалить весь catalog из API/выключить refresh — нарушает deployment; отключить logger целиком — скрывает ошибки. Выбран прямой отказ от ненужных операций без новых настроек.

## Risks / Trade-offs

- EMPTY больше не подписан на странице подключений, но сохранён в API и выборе вариантов редактора; это явная смена PH-CFG-005-S03.
- Диагностический файл больше не является средством получения ошибки: WARN остаётся с безопасным этапом/категорией/кодом. README должен соответствовать новому поведению.
- Изменение только одной JS-ветки оставляет второй канал успешного вывода; проверить оба и PARTIAL → READY.
- Существующие тесты файлов/I/O заменяются проверками отсутствия записи, исходного message, положительными WARN и прежними HTTP/snapshot-сценариями; запретить формальное прохождение пустыми appender-коллекциями.

## Regression Matrix

| Область | Проверка |
|---|---|
| PH-CFG-005-S01/S03/S05 | Реальная страница, одиночная/общая/save-проверка READY/EMPTY; обычный health виден, нет каталожного toast/подписи; переход предупреждения в успех |
| PH-CFG-005-S02/S04 | PARTIAL/STALE/UNAVAILABLE/unknown видны, null и другие сервисы работают; изоляция owner/revision/context сохраняется |
| PH-CFG-008-S01/S02 | Appender: рутинного INFO нет; при фактическом отказе есть безопасный WARN, проверка секретов и отсутствия throwables |
| PH-CFG-008-S03/S04 | Успех/ошибки/repeat/unavailable не пишут и не меняют файлы; message без suffix; реальный изолированный запуск с seeded старым отчётом и проверкой байтов/mtime; API shape, snapshot и fallback |
| Общая регрессия | Профильные suites, полный mvn test на JDK 17, существующий JS contracts и функциональный браузерный проход |

Тесты только в временной копии pom.xml/src/проверенного config/application.properties с относительной H2. Пользовательские БД, логи, кеши и экспорты не копируются, HTTP подменяется. Используется /workspace/perfhub-tools/env.sh; runtime-процесс запускается отдельно на тестовой БД. Проверки браузера идут через установленный Playwright/Chromium с синтетическими HTTP-ответами, без корпоративных интеграций.

## Rollback

Вернуть успешные UI-сообщения и прежний диагностический writer/INFO только отдельным изменением при необходимости. Сохранённый каталог и старые отчёты миграции или удаления не требуют.
