# Spec Delta

## MODIFIED Requirements

### Requirement: PH-CFG-005 Обновление каталога deployment через проверку Grafana

Система SHALL обновлять каталог рендера DropApp и deployment после успешной проверки Grafana, включая сохранение подключения. API SHALL возвращать результат каталога отдельно от доступности Grafana; UI SHALL скрывать успешные READY/EMPTY и показывать ошибки. Каталог SHALL учитывать пользователя, подключение, datasource, namespace и dashboard без изменений настроек и результатов НФТ.

#### Scenario: PH-CFG-005-S01 Проверка и последующий выбор

- **GIVEN** проверка Grafana и чтение метаданных/списка deployment успешны
- **WHEN** пользователь сохраняет подключение либо выполняет его проверку
- **THEN** возвращаются прежние service/success/message и отдельное состояние каталога; конкретные deployment доступны в редакторе шаблона без нового корпоративного запроса при каждом открытии строки.

#### Scenario: PH-CFG-005-S02 Grafana доступна, каталог не обновился

- **GIVEN** проверка доступности успешна, но обновление каталога завершилось ошибкой либо формат не поддержан
- **WHEN** завершается проверка
- **THEN** доступность Grafana остаётся успешной, ошибка каталога видна отдельно; исправные параметры подключения не откатываются по этой причине, последний корректный каталог того же контекста сохранён и помечен устаревшим.

#### Scenario: PH-CFG-005-S03 Успешный пустой список

- **GIVEN** источник корректно вернул пустой список deployment
- **WHEN** обновление завершено
- **THEN** API возвращает EMPTY и время обновления, на странице подключений нет отдельного сообщения каталога; новые deployment выбрать нельзя, прежние строки шаблона не удаляются и не меняются.

#### Scenario: PH-CFG-005-S04 Другой пользователь или контекст

- **GIVEN** сохранён каталог другого пользователя, подключения, datasource, namespace или dashboard
- **WHEN** открыт редактор либо изменены параметры подключения/контекста
- **THEN** чужой каталог не предлагается как актуальный список; обновление не изменяет каталог другого пользователя, а ответ старого контекста не подменяет новый.

#### Scenario: PH-CFG-005-S05 Успех в каждом способе проверки

- **GIVEN** обновление каталога вернуло READY или EMPTY
- **WHEN** проверка запущена для одного источника, для всех подключений либо при сохранении подключения
- **THEN** обычный результат подключения отображается, а строка «Каталог: …», её дата/tooltip и отдельный toast `catalog.message` отсутствуют; при смене прежнего ошибочного результата на успешный прежняя подпись предупреждения удаляется. PARTIAL, STALE, UNAVAILABLE и неизвестный неуспешный статус продолжают отображаться отдельно.

## ADDED Requirements

### Requirement: PH-CFG-008 Проверка каталога без рутинной диагностики

Система SHALL не создавать и не обновлять диагностические отчёты каталога Grafana и SHALL не записывать рутинное INFO-резюме проверки. Результат каталога SHALL возвращаться без дополнений о файле/ID проверки. Безопасные WARN фактических отказов каталога SHALL сохраняться. Это требование заменяет автоматическое сохранение, уведомление о файле и fallback при ошибке его записи по ранее применённому PH-CFG-007; остальные правила обновления каталога и выбора deployment сохраняются.

#### Scenario: PH-CFG-008-S01 Отсутствие рутинной записи

- **GIVEN** попытка обновления завершилась любым состоянием каталога
- **WHEN** диагностический сервис публикует результат
- **THEN** он не создаёт INFO-резюме Grafana catalog check/result/updated/failed/globalFailures/omitted; статус, исходное сообщение и время результата сохраняются.

#### Scenario: PH-CFG-008-S02 Сохранение предупреждений

- **GIVEN** произошёл фактический отказ чтения dashboard/deployment, контекста или локального snapshot
- **WHEN** диагностический сервис обрабатывает отказ
- **THEN** соответствующая безопасная WARN-запись содержит этап/категорию/HTTP-код при наличии, не содержит токенов, сырого ответа, URI или stack trace; отсутствие INFO не подавляет другие логи приложения.

#### Scenario: PH-CFG-008-S03 Отсутствие записи и сохранение старых файлов

- **GIVEN** выполняется новая проверка с любым исходом; старый диагностический файл может существовать, а каталог logs может быть недоступен
- **WHEN** формируется результат
- **THEN** сервис не создаёт logs, постоянные или временные отчёты, не изменяет и не удаляет прежние файлы; доступность каталога logs не влияет на исход проверки. Повторный запуск также не пишет отчёт.

#### Scenario: PH-CFG-008-S04 Исходное сообщение и работа deployment

- **GIVEN** проверка возвращает READY, EMPTY, PARTIAL, STALE либо UNAVAILABLE, включая fallback при неожиданном отказе refresh
- **WHEN** результат передаётся в API и UI
- **THEN** поля catalog.status/message/updatedAt и верхнеуровневые service/success/message сохраняют формат; message не дополнено путём отчёта, ID проверки или ошибкой записи файла. Обновление deployment, старые snapshots и ограниченный resources-fallback продолжают работать как прежде.
