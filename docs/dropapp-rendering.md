# Графики DropApp в шаблонах

Реализация изменения [support-dropapp-repeated-panels](../openspec/changes/archive/2026-10-22-support-dropapp-repeated-panels/proposal.md). Стек, обычный рендер и оценка НФТ сохраняются; результаты проверок и ограничения — в [журнале Apply](../openspec/changes/archive/2026-10-22-support-dropapp-repeated-panels/verification.md).

## Каталог и контекст

После успешной проверки подключения Grafana обновляется отдельный каталог изображений. Сохранение подключения использует ту же проверку. В ответ добавлено поле `catalog` с `status`, `message`, `updatedAt`: READY, EMPTY, STALE, UNAVAILABLE или PARTIAL. Ошибка каталога не меняет успешный health и не должна откатывать исправные credentials. Редактор шаблонов читает локальные данные; открытие списка не вызывает Grafana.

Нормализатор понимает Classic `dashboard.panels`/`templating.list`, вложенные rows и элементы Panel в RowsLayout/GridLayout. Для развёрнутых Classic rows учитывается следующий за row участок плоского массива до следующей row. Scope назначается только панели строки repeat по deployment, запросы которой зависят от deployment напрямую либо через переменные. Сами rows и динамические копии не становятся вариантами графика. Неизвестная структура не публикуется как пустой каталог. Обновление не вызывает discover НФТ и не записывает query/threshold/is_test_query.

Обычные варианты редактора приходят из прежнего сохранённого каталога: snapshot не предлагает новую обычную панель, отсутствующую в прежнем lookup. Новые scoped-панели доступны из snapshot без обязательного discover НФТ. Неизвестное вложенное repeat не преобразуется в формулу reference по догадке.

Deployment разрешается узким Prometheus-адаптером: `label_values(<selector>,deployment)` в строке либо query object (`qryType=1`). Selector после подстановки конкретного namespace передаётся буквально в `match[]` Grafana datasource proxy `/api/v1/label/deployment/values`; кавычки и метрика не исправляются. `label_values` не отправляется как PromQL. Datasource берётся из определения переменной и настроенного значения `${datasource}`. Неизвестные зависимости/тип query, неопределённый datasource/namespace и неподдержанный regex дают отдельную ошибку каталога. Пустой regex, обычный regex и slash-форма без flags либо с `i` поддерживаются; именованные группы text/value сохраняют отображаемый текст отдельно от значения. All исключён из выбора.

Snapshot хранится в новых таблицах `grafana_render_sources` и `grafana_render_snapshots`, отдельно для пользователя, revision подключения, dashboard и datasource/namespace. Секреты не копируются в snapshot. Revision меняется при изменении base-url/api-key/render-path; размеры и timezone уже входят в ключ PNG и не требуют инвалидации каталога. Изменение сохранённых datasource/namespace скрывает другой контекст. Запоздалый результат старой revision не публикуется; DB-транзакция публикации не включает HTTP. Ошибка помечает прежний snapshot устаревшим, EMPTY сохраняет успешный пустой список. Шаблоны при обновлении каталога не переписываются.

## Строка и рендер

В редакторе графиков подходящая панель требует один конкретный deployment из каталога. Все его pod/container отображаются одним PNG. Повторное добавление той же панели для другого deployment сохраняет отдельную строку и порядок. Старое исчезнувшее значение можно оставить без изменения; новое значение должно присутствовать в каталоге. Успешный пустой каталог показывает отсутствие доступных deployment отдельно от ошибки/недоступности; сохранённые строки остаются доступны для исторического запроса. Импорт проверяет форму scope/deployment и без доступа к каталогу, включая `validateCharts=false`; старые обычные панели остаются допустимыми. Распознанная старая DropApp-строка без deployment требует явного выбора.

В строке добавлены nullable `render_scope` и `deployment`, scope — `DROPAPP_DEPLOYMENT`. API save/import принимает `renderScope`, `deployment`; read возвращает также `templateChartId`. Сохранение пересоздаёт id, после него UI перечитывает шаблон. Служебный id не переносится экспортом. Числовой panelId остаётся базовым идентификатором.

Одиночный `/api/grafana/panels/range/panel` дополнительно принимает `templateChartId`. Чужой/устаревший id и несовпадение панели возвращают прежнюю форму 400/message. Запрос без id допустим для однозначной панели; разные deployment одной панели требуют id. Scope и deployment берутся из шаблона, произвольный override запроса не используется.

Рабочий маршрут UID/slug, bearer и fallback slug сохранены. Для подтверждённой строки Grafana 13.0.1 внутренний reference имеет вид `<deployment>$panel-<baseId>`. Переменные копируются на строку: deployment заменяется её значением, pod/container — `$__all`; общие значения не записываются. Неизвестный All/custom all не заменяется догадкой. Серии usage/request/limit и оформление остаются в Grafana. Имя изображения — пользовательское название с `[deployment: значение]`; обычное название не меняется.

PNG-ответ дополнительно содержит `templateChartId`, `deployment`, `templateChartOrder` для восстановления порядка между группами dashboard. Период загружает строки последовательно, продолжает после ошибки и сохраняет timeout 30 с; поздний ответ другого запуска не применяется. Интерфейс тестов при повторном открытии проверяет серверный cacheOnly вместо доверия старому HTML по одному testId. Это локальный запрос PerfHub, не обращение к Grafana.

## Кеш, размеры и ошибки

Обычный ключ кеша не меняется. Для DropApp в `variables_hash` добавляется версионированный контекст пользователя/revision, datasource/namespace, определения панели, deployment, reference и стратегии All. Служебные поля не отправляются как `var-*`. Id строки не входит в ключ байтов: одинаковые параметры переиспользуют PNG, обе строки остаются в результате. Диапазон без testUuid по-прежнему не сохраняется постоянным кешем. forceRefresh/cacheOnly сохраняются; cacheOnly не читает метаданные из Grafana. Смена контекста во время рендера отклоняется до возврата/записи PNG.

Ширина и высота берутся из существующих общих настроек. Целевые 1000×1000 задаются владельцем через них; жёсткого override и новых настроек размера нет. В пользовательскую БД/production-конфигурацию агент значения не записывает. Размеры входят в ключ кеша и разметку отчёта.

Пустое тело/non-PNG/транспортная ошибка не становятся успешным изображением или кешем DropApp. Корректный PNG «No data» возвращается без анализа изображения и подстановки другого deployment. Bulk прекращается при первой ошибке. Подготовка всех изображений предшествует записи отчёта; порядок и отдельные attachments сохраняются. Правила НФТ, пороги, статусы и окна не меняются.

## Откат

Перед использованием новой версии сохранить экспорт прежних шаблонов штатным интерфейсом. При откате сначала восстановить прежние шаблоны/удалить scoped-строки, затем вернуть прежний код по отдельной команде владельца; старый код не умеет читать deployment и иначе может отрисовать другую область. Добавочные nullable-колонки и таблицы можно оставить: старый код их не использует. Служебный scoped-кеш не совпадает с обычным ключом. Удаление новых таблиц/колонок — отдельная операция после проверки данных, не часть автоматического отката. Archive/sync и Git-операции автоматически не выполняются.
