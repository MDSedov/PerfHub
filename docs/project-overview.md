## Назначение и пользователи

**A.** PerfHub объединяет результаты нагрузочных тестов, графики, сведения о стенде и подготовку отчётов. Приложение обнаруживает интервалы нагрузки по данным VictoriaMetrics, сохраняет их, позволяет сопоставить измерения с порогами Grafana, зафиксировать конфигурацию DropApp и опубликовать материалы в Confluence. Jira дополняет конфигурацию сведениями о релизе и дистрибутивах. Отдельный API использует GigaChat для анализа метрик.

**A.** В системе две роли: `USER` и `ADMIN`. Авторизованный пользователь работает с тестами, графиками, отчётами, настройками подключений и собственным профилем. Администратор дополнительно управляет пользователями и справочником типов тестов. Настройки подключений персональные, но тесты, шаблоны, стенд и большинство остальных данных общие. **D.** Должностные роли «инженер НТ», «руководитель тестирования», «владелец релиза» логичны для назначения продукта, но отдельными правами в коде не представлены.

## Типичный жизненный цикл

**A, восстановленная последовательность доступных действий**, а не проверенный сквозной сценарий:

1. Пользователь входит; администратор при необходимости создаёт учётные записи и типы тестов.
2. Пользователь настраивает подключения, загружает каталог Grafana, выбирает панели, шаблоны и состав стенда.
3. На странице «Тесты и отчёты» запрашивает данные за 30 дней. Фоновый мониторинг также может обнаруживать текущие тесты при наличии глобальной конфигурации VM.
4. Отбирает сохранённые тесты по релизу, типу, длительности, периоду, результату проверки и наличию конфигурации. Уточняет тип, комментарий, статус и выводы отчёта.
5. Просматривает графики и конфигурацию, запускает проверку числовых требований, при необходимости повторно снимает конфигурацию стенда.
6. Выбирает тесты и шаблоны, родительскую страницу Confluence; создаёт страницу релиза и отчёты, добавляет ссылки. Отдельная страница позволяет выгрузить графики произвольного периода в существующую страницу.

## Границы и ограничения

**A.** PerfHub не запускает генератор нагрузки и не управляет Kubernetes-ресурсами: обнаруженные вызовы DropApp читают данные. Нет собственного мониторингового хранилища временных рядов; измерения поступают из VM, графики — из Grafana. Отчёты публикуются в Confluence, локально сохраняются шаблоны и отдельные метаданные ссылок. Интеграционные полномочия зависят от настроенных внешних учётных данных.

**C/D.** Нет доказательства полной многопользовательской изоляции, корректности всех legacy-страниц или успешной работы конкретных корпоративных подключений. Не обнаружены маршруты запуска теста, полноценного управления проектами, удаления теста пользователем или управления промптами через UI. Это границы найденной реализации, а не доказательство отсутствия внешних потребителей.

После согласования и штатного завершения baseline OpenSpec является источником утверждённых требований. Документы описывают A; принятые формулировки фиксируют исследованный AS-IS. Дефекты и спорные особенности вынесены в [реестр решений](requirements/gaps-and-decisions.md).

Стек фиксирован: Java 17, Spring Boot/MVC, Thymeleaf, Bootstrap 5, Vanilla JavaScript, Maven и существующее хранение. Изменение стека требует отдельного OpenSpec-предложения и явного согласования владельца. Версии определяются текущим `pom.xml`; в этом задании не изменены.
