# Прослеживаемость требований PerfHub

Baseline `baseline-existing-perfhub` официально согласован владельцем 12.10.2026, исходники `main`/`f3498db`. [Результат review](baseline-review.md). **A** означает факты реализации, **B** — последующие неутверждённые предложения; ошибки и нерешённые политики **C/D** находятся в [реестре](gaps-and-decisions.md). После штатного переноса ссылки требований ведут в основные specs.

## Уровни доказательств

- **Код**: изучены вызывающие маршруты/условия и связанные исходники, а не только наличие имени класса.
- **Тест (частично)**: существующий тест проверяет перечисленную часть поведения. Это не полное покрытие всех сценариев требования и не проверка реальной интеграции.
- **Приложение**: проверка работающего приложения; на этом проходе таких доказательств нет.
- **Не подтверждено**: нет достаточного свидетельства; спорные legacy/эксплуатационные возможности перечислены после матрицы.

Предыдущий изолированный `mvn test` для неизменного среза исходников: 130 тестов/25 классов, 0 ошибок и падений, Java 21.0.11 с release=17. В текущем проходе Maven повторно не запускался. Подробности и ограничение файловой H2 — [G-02](gaps-and-decisions.md#g-02). Связи с методами тестов проверены по исходникам; тесты и результаты не добавлялись.

## Сопровождение

Новые ID выдавать последовательно в соответствующей области; не переиспользовать старые. При изменении требования в OpenSpec одновременно обновлять строку матрицы, сценарии и реестр решений. После штатного archive проверить ссылки на основные specs, сохранив историю ID. Утверждение владельца и его дата фиксируются только по фактическому решению; принятое 12.10.2026 решение отражено в протоколе review.
